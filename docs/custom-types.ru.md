# Пользовательские типы и повторные Rust-структуры

QslCustom задаёт точные SIZE и COMP_SIZE, проверки wire-байтов/значений и явные unsafe-методы по указателям. Обе проверки должны подтвердить домен до вызова trusted-кодека из checked-пути. При изменении COMP_SIZE нужны соответствующие compact-чтение и запись: стандартные методы используют обычный кодек. Текстовые массивы допускают встроенные и явно зарегистрированные примитивы.

## Пользовательские примитивы

Макрос внедрения полей и полиморфный кодек — разные механизмы. Существующие реализации `QslCustom` сохраняются. Автоматической замены их формата на встроенный числовой тип нет.

В общем Rust-модуле приложения и build-скрипта:

```rust
qsl_lexer::qsl_primitive!(pub struct DeviceId(u32);range=(1,100););
```

Поддерживаются u8/i8, u16/i16, u32/i32, u64/i64. Макрос проверяет вид числа, размер, выравнивание, смещение поля, отсутствие Drop и допустимость диапазона. Обычный кодек записывает little endian. Компактный кодек хранит ранг `value-min` минимальным целым количеством байт. Соседние встроенные поля с ним автоматически не объединяются в один регистр. Постоянный диапазон занимает 0 компактных байт; ограничения PS на нулевую ширину optional-кодека сохраняются.

```rust,ignore
use qsl_interpreter::prelude::*;
let builder = QslSchemaBuilder::new()
    .with_primitive::<DeviceId>("DeviceId")?
    .with_source("&Packet[safety,compact,optionals=bitmap,opt_table]{DeviceId id;DeviceId? extra;}")?;
let rust = builder.use_interpreter()?;
```

Регистрация предшествует разбору. Rust проверяет ABI также в приложении через сгенерированные константные утверждения, включая элементы массивов. Зарегистрированный примитив допускается внутри QSL-массива. После импорта Rust-шаблонов метаданные применяются повторно.

Для использования в нативном регионе приложение отдельно вызывает `qsl_lexer::qsl_native_primitive!(DeviceId,u32);`. Макрос использует существующий `NativeField` и проверяет значение до создания безопасного представления. Произвольные ручные `unsafe impl` остаются обязанностью разработчика: сравнение размеров не доказывает семантику его методов. Широкая автоматическая трансмутация пользовательских типов не добавляется. Вложенная схема внутри кодека имеет собственную область optional-маркеров.

## Вложенные структуры регионов

```qsl
&Parent[safety] {
    #region(aggressive_transmutate="Meta");
    u64 id;
    u32 value;
    str(4) tag;
    #end_region;
    str(3..10) name;
}
```

Генерируются самостоятельная `#[repr(C)] Meta { id:u64, value:u32, tag:[u8;4] }` и `Parent { Meta:Meta, name:String }`. Поля региона не раскрываются обратно в Parent. Старое написание `aggresive_transmutate` принимается как синоним.

COPY создаёт собственный объект; при несовпадении native- и wire-layout использует сборку по полям. LIFETIME создаёт ссылку только после проверки размера, смещений, little endian, выравнивания входа и всех значений. Обычный Vec не гарантирует выравнивание произвольной структуры: при нарушении checked-чтение возвращает ошибку. COPY такого выравнивания входного адреса не требует.

Вложенные регионы создают иерархию типов. Повторные идентичные определения переиспользуются. Конфликты имён, рекурсия, пересекающиеся или пустые регионы, неизвестные native-типы, динамические и optional-поля внутри региона отклоняются. Фиксированные строки представлены `[u8;N]`; лимит стека действует и для native-строк/массивов. Native-дескриптор допускает до 64 инициализированных листьев, вложенность регионов ограничена 64.

Rust-шаблон `#[qsl::schem_macro(aggressive_transmutate)]` сохраняет исходный Rust-тип как вложенное поле без дублирующего определения. Обычные макросы внедрения полей продолжают раскрываться. Явный `repr(align(...))` учитывается; дополнительный padding может исключить LIFETIME при доступном COPY.
