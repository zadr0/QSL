Опциональные поля: длина и теги

predict_seq: индекс по длине

predict_seq отвечает за определение присутствия полей по длине, а не за выбор читателя по тегу. Самостоятельный режим не записывает теги: для одного optional-поля используется EOF, для нескольких — числовой индекс статической таблицы уникальных сумм фиксированных размеров. Неоднозначные суммы, нулевой размер единственного поля и превышение бюджета отклоняются. Нужен вход с известной длиной; deserialize_unsafe(ptr) без длины не поддерживается.

opt_table: читатель по тегу

opt_table генерирует статическую таблицу функций чтения, индексированную реальным тегом схемы: readers[tag - 1]. Это не ordinal опционального поля: теги обязательных полей оставляют пустые записи. Перед доверенным вызовом checked-курсор проверяет допустимость тегов, их порядок, отсутствие повторов, границы и значения всего кадра. Обработчик возвращает число прочитанных байтов, чтобы продвинуть курсор без повторного вычисления длины.

Самостоятельный [opt_table] сохраняет обычный wire-формат и его хэши. При нескольких полях сначала читаются число и упакованные теги из заголовка, затем вызываются читатели присутствующих полей; у одного optional-поля достаточно признака присутствия, а его тег известен из схемы. Таблица не выделяется на сообщение. Размер таблицы — max_tag указателей Option; на x86-64 каждый элемент занимает один машинный указатель. Само наличие таблицы не гарантирует ускорение: косвенные вызовы и подготовка результата тоже стоят времени.

predict_seq + opt_table: сохранённый граф длин

[predict_seq,opt_table] сохраняет байтовый формат и хэши прежней смешанной реализации [opt_table]. predict_seq определяет событие длины; opt_table предоставляет читателя разрешённого поля. Отдельные функции больше не подменяют эти назначения.

После метаобласти и обязательной части вычисляется длина optional-payload L. Числовой индекс: I(L) = sum((L > c_j) as usize). В событии известны гарантированные и возможные поля. Для двух optional-u8: I=(L>0)+(L>1); L=0 означает отсутствие обоих, L=2 — наличие обоих, L=1 требует метаданных для выбора a или b. Пропуск чтения метаданных не удаляет зарезервированный байт из кадра. Когда тег не записан отдельно, он известен генератору по разрешённой позиции поля.

Для строк 3..33 и 1..255 границы вычисляются из диапазонов. CRITICAL_POINTS и граф событий относятся к predict_seq; OPT_TABLE — к диспетчеризации читателей. Общий граф ограничен 12 полями и 65535 payload-байтами; равные фиксированные ширины поддерживаются до 64 полей. Если граф неприменим, используются проверяемые EOF, точная таблица длин либо явная маска присутствия. Это не обещание отсутствия ветвлений во всём decoder.

opt_table=legacy — отдельный прежний каталог смещений внутри сообщения. Числовая специализация QPS и её подготовленное ядро не содержат обычных тегов: они используют собственные битовые смещения; opt_table не заставляет их применять байтовую таблицу. В сочетании со state_bits присутствие берётся из D, а чтение optional-полей использует таблицу читателей. Внешний общий QPS сначала восстанавливает внутренний кадр.

Переход и прежние замеры

Для старого кадра [opt_table] укажите [predict_seq,opt_table] на обеих сторонах. Новый отдельный [opt_table] совместим с default, но в общем случае не со старым смешанным форматом. Автоматического определения версии нет. Прежние результаты с подписью opt_table, включая ускорение 1,46–1,73 раза в examples, измеряли смешанный граф длин. Они не являются замерами новой таблицы по тегам; исходные JSON, исходники и числа сохранены.

Ограничение самостоятельного tag-пути: optional_count * tag_bits <= 64; compact и bitmap не сочетаются с opt_table. Для более широкого хвоста выбирается совместимый combined/state_bits/legacy-режим по его собственным ограничениям.
