QSL — архитектурный и технический справочник




Статус документа: основан на предоставленных архивах QSL.rar, qsl-demo.rar, qsl-bench(1).rar и экспортированных измерениях. Обозначения Реализовано, Ограничение, Проектируется отражают проверенные исходники, а не общий замысел. Формат QSL не является автоматически безопасным для произвольного сетевого ввода.




1. Что представляет собой QSL


QSL (схемо-ориентированный DSL для бинарной сериализации) описывает типы, порядок полей, диапазоны, опциональность и способ представления. Парсер переводит DSL в QslSchema / QslField / QslType, после чего QslInterpreter генерирует код Rust. Вычислимые заранее маски, смещения, длины и ранги переносятся в генерацию; runtime получает специализированные методы. Исходники .qsl описывают схемы; .deq — типизированные числовые константы, а не пути сборки.


Цель проекта — сократить стоимость конкретной операции над известной схемой, а не гарантировать лидерство любого сценария. Результат зависит от компоновки данных, владения памятью, длин строк, аллокаций, кэша, инструкций компилятора, CPU, количества записей и транспорта. Генератор может удалить универсальный разбор схемы из горячего пути, но не физические расходы на перемещение данных и выделение памяти.


Пример фактического DSL из qsl-demo/schemas/fixed.qsl:


&Fixed {
    u32 id |default=1|;
    u64 created_at;
    u16 checksum;
}
&Dense[compact] {
    u8(0..7) flags;
    u8(0..31) rank;
    u16(0..1023) code;
}



Здесь Fixed содержит 14 байт wire payload с постоянными смещениями 0,4,12; Dense упаковывает 18 бит = 3 байта. Точные байты зависят от значений. Default — инициализация Rust-объекта, а не отдельное поле на wire.

3. Математическая основа


3.1 Ранг ограниченного целого


Для целочисленного включительного диапазона [MIN, MAX]:


N = MAX - MIN + 1,    B = ⌈ log₂ N ⌉,    r = x - MIN



Эквивалентный расчёт B — битовая длина MAX-MIN, без f64. Примеры: 10..17 → 3 бита; -5..10 → 4 бита; 5..5 → 0 бит. В compact пишется беззнаковый ранг r, а не исходное представление x. Диапазон проверяется на этапе описания схемы; trusted runtime требует от вызывающего кода MIN ≤ x ≤ MAX.


3.2 Позиция, выравнивание и фиксированная длина


Для последовательных битовых полей o_(i+1) = o_i + B_i; байтовая длина ceil(total_bits / 8). В реализации встречаются (bits + 7) >> 3 и (bits + 7) & !7 для округления/выравнивания к границе байта. alignment запрашивает выравнивание после каждого поля в compact-потоке. Не следует автоматически приписывать этому ускорение: LLVM может самостоятельно оптимизировать div_ceil с константой.


3.3 Метаданные присутствия


Обычная запись одного optional без bitmap использует бит присутствия; нескольких optional — количество присутствующих и последовательность назначенных компилятором тегов. tag=index+1, пользовательский |tag=N| отвергается; tag-1 хранится с шириной ceil(log2(max_tag)). Схема с max_tag=8 использует 3 бита для тега. optionals=bitmap использует ceil(fields / 32) слов u32 LE, с расположением полей от MSB к LSB внутри слова.


3.4 Стоимость таблицы


При opt_table для K ≥ 2 optional полей каталог имеет 1 + 4K байт: count:u8 и K смещений u32 LE, после которых идут данные присутствующих полей. 0 означает отсутствие; offset+1 — присутствие, смещение относительно начала optional payload. Индексация — O(1) по индексу, декодирование всех полей — O(K). Экономия на множестве поисков оплачивается размером таблицы.


4. Атрибуты схем: справочник и инварианты


compact — битовая упаковка


Статус: реализовано. Применяется как &Dense[compact]. Ранжированные числа занимают минимальную ширину B, флаги и целые обрабатываются битовым курсором. Генератор в случае полностью фиксированных полей может развернуть маски и сдвиги до констант и упаковать данные 64-битными словами. Типовые методы: comp_size(), comp_write(), unsafe comp_read(); в обычной структуре эти методы не генерируются.


Ограничения: последовательные режимы predict_seq/opt_table несовместимы с compact; данные переменной длины всё равно требуют чтения префикса и полезной нагрузки. Битовая упаковка не равна универсальному сжатию строк или векторов. Для значений вне диапазона unchecked-запись не выполняет runtime-валидацию. Если все поля уже занимают стандартный размер и данные читаются по одному, дополнительная битовая логика может не окупиться.


Пример: flags:0..7 = 3 бита; rank:0..31 = 5 бит; code:0..1023 = 10 бит. Итого 18 бит. Даже здесь byte-oriented Fixed может быть быстрее на отдельных CPU.


alignment — границы полей


Статус: реализовано. &Schema[compact,alignment] выравнивает курсор до ближайшей границы байта после каждого поля. Генератор вставляет reader.align() и соответствующие действия записи; это изменение wire layout. Ограничения: отсутствует польза, если поле уже заканчивается на байтовой границе. Увеличивает размер при неполных байтах; снижение затрат на неоднозначные битовые границы необходимо проверять бенчмарком. Не является обещанием выравнивания каждого поля на 8/16/64 байт в физической памяти.


optionals=bitmap — карта присутствия


Статус: реализовано. Один бит на каждое поле, включая обязательные. У обязательных бит равен 1, свободные биты последнего слова — 0. Первое объявленное поле соответствует 1u32 << 31 первого u32, второе — 1u32 << 30; сами слова передаются little-endian.


Ограничения: метаданные занимают 4 байта на каждые 32 поля; для единственного optional это может быть больше, чем один presence bit. opt_table и predict_seq несовместимы с bitmap. Изменение порядка полей меняет соответствие битов. Bitmap показывает наличие, но не местоположение произвольной строки без последовательного чтения предшествующих переменных полей.


predict_seq — присутствие по EOF


Статус: реализовано. Форма &SeqNumber[predict_seq] { u64 id; u32? extra; }. Wire имеет [обязательный payload][опциональный payload?], без presence bit и тега. Если весь буфер длиной 8 байт — None; если 12 байт — Some(u32). После чтения обязательной части генератор проверяет, остались ли байты, а затем читает optional.


Ограничения: строго один optional, он идёт после всех required; compact, optionals=bitmap и opt_table вместе с predict_seq запрещены. Нулебайтовое присутствующее optional поле неразличимо с None и отклоняется. API deserialize_unsafe(ptr) паникует для predict_seq, требуется длина: deserialize(&slice) или deserialize_from_raw_parts(ptr,len). На неполном хвосте (например 10 байт вместо 12) len > 8 сам по себе не гарантирует доступность полного u32: вход обязан быть валидирован до unsafe-чтения. Наличие не гарантирует branchless-asm и не отменяет зависимую загрузку.


opt_table — статически индексируемый каталог


Статус: реализовано. &TableFields[opt_table] { u64 id; u32? a; str?(0..100) text|decompress=true|; u16? b; }. Для ≥2 optional записывается каталог count + offsets, после него идут присутствующие значения. Индексы совпадают с порядком объявления; отсутствующие записываются нулём, присутствующие — offset+1. Отдельный тип OptionalOffsets<'a> проверяет метаданные и даёт offset(i), field_tail(i).


Ограничения: обязательные поля должны стоять до опциональных; несовместим с compact, bitmap, predict_seq. Размер каталога 1 + 4K байт, оффсеты — u32, максимум 64 опциональных индекса по текущему валидатору. OptionalOffsets::parse проверяет каталог, но не содержимое каждого значения/UTF-8. Для одного optional opt_table намеренно использует EOF-семантику predict_seq, без каталога. Добавление второго optional меняет формат. При ≥2 optional добавление нового поля в конец сохраняет индексы старых; изменение типов, порядка и required-layout требует новую версию схемы.


lifetime — заимствование из входного буфера


Статус: реализовано. &View[lifetime] { string text; } генерирует View<'a> с &'a str и BorrowSerializable<'a>. Буфер-источник должен сохраняться и оставаться неизменным в течение 'a. Скалярные поля остаются значениями.


Ограничения: lifetime не устраняет стоимость передачи, фрейминга и последующих неравномерных чтений; при потребности владеть результатом может понадобиться копия. Не все custom/array layouts допускают borrowing. Источник не должен быть освобождён или мутирован, пока действуют ссылки. binary_opt может добавить lifetime только для конкретного поля без перевода остальных String в borrowed.


safety — флаг схемы, не гарантия сетевой проверки


Статус: распознаётся парсером и сохраняется в флагах. В предоставленном генераторе FLAG_SAFETY не влияет на выбор сгенерированного декодера: deserialize и deserialize_unsafe по-прежнему unsafe; checked I/O существует отдельно под Cargo-feature diagnostics. Поэтому не следует считать, что &Packet[safety] самостоятельно валидирует сетевые данные. Для недоверенного транспорта вызывающий код обязан проверить длины, границы, UTF-8, версии схемы и значения до unchecked-декодирования.


default=EXPR — значение инициализации


Статус: реализовано. Поле u32 id|default=7|; получает числовое значение в генерируемом Default; u32? x|default=7|; в объекте по умолчанию получает Some(7). При чтении отсутствующего optional возвращается None, а не Some(default). Функция unwrap_or_default() не является частью необходимого wire-декодирования. Ограничения: числовые compile-time выражения и проверка диапазонов; произвольные строки и custom defaults не поддерживаются текущей генерацией.


5. Полевая атрибутика строк


binary_opt=false / отсутствие модификатора


Обычное str создаёт String (или &'a str при явном lifetime). Для owned-декодирования строка создаёт аллокацию; при малых сообщениях именно стоимость аллокации способна доминировать. Длина динамической строки на wire измеряется UTF-8 байтами, не числом Unicode-символов.


binary_opt=true — заимствованные байты


Генерирует &'a [u8]. Это borrowed/zero-copy чтение исходного wire payload: декодер не выделяет отдельный String. Семантика остаётся строковой, и доверенный input обязан соответствовать корректному UTF-8, хотя тип Rust &[u8] сам по себе этой корректности не доказывает. Если пользователь копирует срез позже, копирование уже относится к уровню приложения. Для binary_opt=true с decompress=true заимствование декодированного сжатого содержимого запрещено.


binary_opt=guard — типизированный view


Генерирует qsl::Utf8Guard<'a> — срез байтов с lifetime, а не самостоятельно выделенная копия/арена. Utf8Guard::from_str не аллоцирует и не сканирует; try_from_bytes один раз валидирует UTF-8; from_bytes_unchecked требует гарантий от вызывающего. as_str, as_bytes, Deref<Target=str> дают удобный доступ. Контроль владения обеспечивается borrow checker. Проверенная валидация UTF-8 и trusted view — разные операции и должны измеряться отдельно.


binary_opt=inline — владеющее inline-хранилище


Для ограниченных строк str(0..MAX) (MAX ≤ 65535) создаёт InlineString<MAX> с u16 длиной и встроенным массивом байтов. Отдельной аллокации String нет, но размер Rust-объекта определяется максимальной ёмкостью. Возврат большого объекта по значению может стоить дороже его декодирования; deserialize_into пишет непосредственно в итоговую память и уменьшает стоимость перемещения.


decompress=true — QSL-LZ v1 / fixed v2


Для ограниченной строки создаёт InlineString<MAX>; используется детерминированный QSL-LZ без heap scratch, с ограниченным поиском совпадений. Если сжатый кадр вместе с заголовком не меньше raw payload, выбирается raw режим. Нет гарантии, что произвольный UTF-8 станет меньше исходных байтов; raw fallback сохраняет корректность. Длина строки, сжатие и распаковка могут нарушить целевое время 25 нс. Для фиксированной str(N) тип всегда [u8;N]; fixed-compressed framing версии 2 содержит либо ровно N raw байт без заголовка, либо 0xFF + длина + токены, общий размер не более N. Обе стороны должны использовать одну версию fixed codec.


Фиксированная str(N) и ограничения


Для str(1024) Rust-представление — [u8;1024] даже при модификаторах binary_opt. Отсутствует runtime-поле длины; размер известен при генерации. UTF-8-ограничение касается байтов; диапазоны и байтовые массивы не означают автоматическую компрессию числа со строкой или всех типов подряд. Заявление «QSL сжимает всё» неверно: QSL применяет определённый кодек к явно помеченным строковым полям, compact — отдельная ранговая упаковка целых.


6. Разбор конкретных структур


Fixed: константные смещения


&Fixed { u32 id|default=1|; u64 created_at; u16 checksum; }



Генератор создаёт struct Fixed { id:u32, created_at:u64, checksum:u16 }, impl Serializable, get_size()=14, serialized_size()=14, serialize_unsafe(), deserialize_unsafe() и другие методы trait. Для flat path запись идёт по литеральным смещениям 0/4/12 через little-endian unaligned store. В wire нет padding Rust-структуры. Узкое место обычно не универсальный парсер, а физическая запись и последующая передача байтов. В Criterion этот путь может быть быстрее или медленнее baseline на доли наносекунды; малые изменения требуют повторов.


Dense[compact]: битовые ранги


&Dense[compact] { u8(0..7) flags; u8(0..31) rank; u16(0..1023) code; }



Поля занимают 3 + 5 + 10 = 18 бит → 3 байта. Генерируются предвычисленные маски, сдвиги и методы comp_*. Для этих трёх полей отсутствует необходимость хранить их типичные Rust-ширины 1+1+2 байта. Недостаток — битовая обработка/краевые случаи, а не обязательно выигрыш по latency.


Packet / Tagged: опциональность и метаданные


&Packet { u64 sequence|default=0|; u16? priority; }
&Tagged { u32 id; u16? a; u8? b; }



Packet в обычном режиме использует один presence bit (округляется до байта), затем u64 и при наличии u16. Tagged с двумя optional использует count + сжатые теги (назначены компилятором), затем значения. Стоимость метаданных и ветвления присутствия может быть заметнее записи маленького числа. opt_table альтернативно оплачивает каталог ради более быстрого выборочного доступа при множестве optional.


SeqNumber[predict_seq]: условный хвост


&SeqNumber[predict_seq] { u64 id; u32? extra|default=7|; }



Размер wire — 8 либо 12 байт. Метод deserialize_from_raw_parts(ptr,len) определяет наличие extra сравнением позиции курсора с len, потом декодирует optional. default=7 влияет на Default, но отсутствие в сообщении — None. Для произвольного len=9..11 такой вывод о присутствии недостаточен, поэтому trusted caller обязан предоставить полную валидную запись.


TableFields[opt_table]: выборочный доступ


&TableFields[opt_table] {
    u64 id; u32? a;
    str?(0..100) text|decompress=true|;
    u16? b;
}



Required id идёт первым; затем count=3, 3 × u32 LE смещений, затем только присутствующие optional значения. Нулевой offset означает отсутствие. Генератор возвращает Option<T> для каждого optional. OptionalOffsets проверяет каталог, но строковый codec и факт пригодности UTF-8 требуется проверять отдельно. Каталог оправдан при множестве optional и повторных точечных обращениях, не при маленьких сообщениях с обязательным полным декодированием.


ByteView, GuardView, StringView, InlineView, PackedView


Все пять примеров из qsl-demo/schemas/lowlevel.qsl описывают до 4096 UTF-8 байт, но генерируют разные Rust-поля. StringView владеет String; ByteView заимствует &[u8]; GuardView заимствует Utf8Guard; InlineView содержит InlineString<4096>; PackedView содержит InlineString<4096> с QSL-LZ wire mode. При сравнениях важно измерять тот же набор Unicode-символов, отличая фактическую длину 1024/2048/4096 байт и отдельную стоимость deserialize_into.


Token: кастомный тип


#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Token(pub u16);
impl qsl::QslCustom for Token {
    const SIZE: usize = 2;
    unsafe fn qsl_write_unchecked(&self, to: *mut u8) {
        std::ptr::write_unaligned(to.cast::<u16>(), self.0.to_le());
    }
    unsafe fn qsl_read_unchecked(from: *const u8) -> Self {
        Self(u16::from_le(std::ptr::read_unaligned(from.cast::<u16>())))
    }
}



Эта реализация использована в qsl-demo/src/main.rs. Схемы &CustomPacket[safety] { Token code; } и &CompactCustom[compact] { Token code; } встраивают вызовы через QslCustom. SIZE и COMP_SIZE должны точно совпадать с реальным количеством записанных/прочитанных байтов. Выравнивание, little-endian и существование допустимого битового представления — ответственность реализации QslCustom. Неверная длина или недействительные указатели могут привести к UB.


7. QslCustom: границы и производительность


QslCustom — compile-time sized интерфейс, а не динамический trait object. Методы qsl_write_unchecked / qsl_read_unchecked предназначены для pointer I/O; qsl_comp_* по умолчанию делегируют обычной реализации; qsl_size и qsl_comp_size возвращают compile-time константы. Это позволяет специализацию и inlining, но не гарантирует отсутствие проверок внутри пользовательского codec.


Причины замедления: дополнительные проверки полей, незаинлайненный вызов, копирование временной структуры, преобразования little-endian, сложные внутренние массивы и неспециализированный пользовательский декодер. Утверждение «custom всегда медленнее» не подтверждено отдельной количественной выборкой в предоставленном Criterion CSV; это объяснение возможной регрессии, а не измеренный закон. Сопоставление должно иметь равный wire-format, исходные значения и контракт безопасности.


Ограничения: константный SIZE обязателен; для predict_seq optional custom SIZE > 0. Арбитрарные массивы переменной длины custom объектов могут отклоняться генератором, когда заранее невозможно определить продвижение указателя. Для direct native transmute нужны отдельные требования к bit validity, padding, alignment, ABI и endianness; самого универсального «transmute codec» эта реализация не предоставляет.


Проектируется: отдельный структурный макрос для генерации QslCustom без ручного повторения проверок и pointer hooks. Его публичный синтаксис/реализация в приложенных исходниках не обнаружены; ниже это архитектурная цель, а не доступная функция.


8. Буферы, прямое чтение и транспорт


serialize() выделяет один результирующий буфер (Vec<u8>, либо SerOut при feature native); unsafe serialize_to() пишет в заранее предоставленное хранилище, не проверяя достаточность ёмкости. SerOut::with_capacity_aligned(capacity,alignment) создаёт переиспользуемую выделенную область; clear() сохраняет ёмкость. deserialize_into(ptr,len,out_ptr) может декодировать inline-поля сразу в итоговый объект, вместо возврата большого InlineString по значению.


RawSocket — обычный TCP с бинарным фреймингом, не raw IP socket. Формат кадра [length:u32 LE][QSL payload]; receive(&mut storage) читает ровно кадр в буфер пользователя и ограничивает размер; send_record пишет payload сразу после префикса; включается TCP_NODELAY. Сам факт корректного TCP-фрейминга не означает проверки всех полей QSL. WebSocket-кампания k6 и raw TCP — разные измерительные сценарии.

QSL — Architecture and implementation reference




Scope: grounded in the supplied QSL.rar, qsl-demo.rar, qsl-bench(1).rar and benchmark exports. Implemented, Constraint, and Planned describe the inspected sources, not the broad design roadmap. QSL does not automatically make arbitrary network input safe.




1. QSL as a schema-specific DSL


QSL is a domain-specific language for binary serialization schema generation. A .qsl file declares field types, order, ranges, optionality and layout. .deq provides typed compile-time numeric constants. QslInterpreter converts the normalized schema to Rust source, with offsets, masks and rank widths determined before runtime. The resulting Rust types implement serialization traits; there is no generic schema interpretation on every record.


The goal is to minimize work for a particular schema and workload, not to claim universal superiority. The result depends on memory layout, ownership, string size, allocation, CPU caches, compiler code generation, concurrency and transport. Moving arithmetic to code generation cannot remove the physical cost of copying data or waking threads.


Actual examples from qsl-demo/schemas/fixed.qsl:


&Fixed {
    u32 id |default=1|;
    u64 created_at;
    u16 checksum;
}
&Dense[compact] {
    u8(0..7) flags;
    u8(0..31) rank;
    u16(0..1023) code;
}



Fixed has a 14-byte wire payload with literal offsets 0,4,12; Dense takes 18 bits = 3 bytes. Rust structure padding does not become wire padding. Numeric default affects initialization, not a separate serialized field.

Separation of concerns: QSL DSL describes layout; QslInterpreter generates machine-compilable Rust; pointer readers/writers execute the record operation. The build-time parser is not run for every socket message.


3. Mathematical foundations


3.1 Integer range ranking


For the inclusive integer range [MIN, MAX]:


N = MAX - MIN + 1,    B = ⌈ log₂ N ⌉,    r = x - MIN



B is the bit length of MAX-MIN and can be computed with integer operations. 10..17 needs 3 bits, -5..10 needs 4, and 5..5 needs 0 payload bits. Compact mode writes an unsigned rank r instead of the original integer representation. Runtime unchecked writers rely on the caller to satisfy MIN ≤ x ≤ MAX.


3.2 Offsets and alignment


Bit-position recurrence: o_(i+1)=o_i+B_i. Wire length is ceil(total_bits/8). The generator/runtime use familiar constant arithmetic such as (bits+7)>>3 and (bits+7)&!7. alignment pads after each compact field to the next byte boundary. A source rewrite of div_ceil is not automatically a speedup; LLVM often strength-reduces constant division.


3.3 Optional-field metadata


Without bitmap, one optional uses a presence bit; multiple optionals use a count and generator-assigned tags. Tags are one-based in declaration order and stored as tag-1 in ceil(log2(max_tag)) bits. With max_tag=8, tag metadata takes 3 bits. optionals=bitmap uses ceil(total_fields/32) little-endian u32 words, with the first field at the most-significant bit.


3.4 Offset table cost


For opt_table with K≥2 optionals, directory bytes are 1+4K: count:u8, followed by K × u32 LE offsets and optional payload. Zero means absent; positive entries store payload_offset+1. Indexed lookup is O(1); decoding all K fields is O(K). A table trades additional wire bytes for easier indexed access.


4. Schema attributes — implementation and limitations


compact — bit-ranked representation


Implemented. &Dense[compact] makes constrained integers occupy their computed rank width rather than the full Rust storage width. Fixed compact paths can be emitted with literal masks/shifts and fully unrolled 64-bit word operations. Compact-generated types expose comp_size(), comp_write() and unsafe comp_read() alongside the serialization trait methods.


Constraints: incompatible with the sequential optional formats predict_seq and opt_table. Variable-length fields still require length and payload processing; compact does not transparently compress mixed numeric-and-string objects. Values outside declared ranks violate the unchecked encoder contract. Additional bit operations may offset size benefits on particular hardware.


Exact example: u8(0..7) = 3 bits, u8(0..31) = 5 bits, u16(0..1023) = 10 bits, total 18 bits and three wire bytes.


alignment — field-end byte alignment


Implemented. &Schema[compact,alignment] rounds the bit cursor to the next byte boundary after each field. The generator inserts corresponding writer operations and reader.align(). This changes the wire format and may simplify subsequent byte operations.


Constraints: wastes bits when preceding widths are not multiples of eight; does not mean 8/16/64-byte physical cache-line alignment. It offers no padding benefit to fields already byte-aligned. Measure cycles rather than assume an automatic speedup.


optionals=bitmap — presence map


Implemented. A bit is present for every declared field, including required fields; required bits must be one, unused trailing bits zero. The first declared field maps to 1u32<<31, the second to 1u32<<30, and so on; each u32 is written little-endian.


Constraints: costs four bytes per 32 fields, potentially excessive for one optional; incompatible with predict_seq and opt_table. Reordering fields changes bit identities. A bitmap indicates presence but does not automatically provide byte offsets into preceding variable-length fields.


predict_seq — EOF-inferred single optional tail


Implemented. &SeqNumber[predict_seq] { u64 id; u32? extra; } encodes [required fields][optional field if present], with no tag or presence header. Wire is eight bytes when absent and twelve when present; presence is inferred after decoding the required prefix.


Constraints: exactly one optional, after all required fields; incompatible with compact, bitmap and simultaneous opt_table. Present zero-byte fields are prohibited. A pointer-only deserialize_unsafe(ptr) intentionally panics: use length-aware deserialize(&slice) or deserialize_from_raw_parts(ptr,len). len>8 only detects an additional suffix; a truncated 9–11 byte message is not a valid u32 suffix. The caller must validate complete trusted input. A source-level boolean comparison does not prove branchless assembly.


opt_table — indexed optional directory


Implemented. For two or more optional fields following all required fields, the writer emits [count:u8][count×u32 LE offsets][present payload]. Entries are zero for absent values, otherwise offset+1 relative to optional payload. Indices are assigned in declaration order. OptionalOffsets::parse/offset/field_tail provides a metadata checker and direct lookups.


Constraints: incompatible with compact, bitmap and predict_seq; requires all mandatory fields before any optional. Directory size 1+4K bytes; offsets fit u32; current validation supports no more than 64 optional indices. OptionalOffsets::parse does not check field codecs or UTF-8. One optional under opt_table uses predict_seq-style EOF layout, not a directory; adding a second optional changes the format. For ≥2 optional fields, appended fields preserve existing indices; changing required layout, ordering or field type requires a schema revision.


lifetime — borrowing the input


Implemented. &View[lifetime]{ string text; } emits View<'a> containing &'a str, with the BorrowSerializable<'a> methods. The backing bytes must remain alive and immutable for the record lifetime. Scalar fields remain value types.


Constraints: custom and non-byte-array cases have borrowing restrictions. Borrowed data cannot outlive its source, and borrowing alone does not remove network framing or copying elsewhere. Per-field binary_opt=true/guard can introduce a lifetime only for that field, without changing unrelated owned strings.


safety — parsed flag, not an automatic checked decoder


Status: parsed and stored. In the supplied generator, FLAG_SAFETY is not used to select a distinct validated read path. deserialize and deserialize_unsafe remain unsafe; optional checked I/O helpers are compiled under the separate diagnostics feature. Do not treat &Packet[safety] as validation of arbitrary network messages. Callers must independently establish field lengths, bounds, UTF-8, values and schema revision before trusted decode.


default=EXPR — numeric initialization


Implemented. u32 x|default=7| sets the generated Rust Default value to seven; u32? x|default=7| initializes to Some(7). When an optional field is absent during decoding, it remains None, not a default-valued Some. unwrap_or_default() is not required by the wire decoder.


Constraints: build-time numeric expressions with range validation; the current generator does not implement arbitrary string or custom-type default values.


5. String field modifiers and ownership


Default str / binary_opt=false


An ordinary string generates String unless explicit schema lifetime yields &'a str. Owned decoding allocates a string and can dominate tiny record timings. Dynamic length measures UTF-8 bytes, not Unicode scalar values or grapheme clusters.


binary_opt=true — borrowed &[u8]


Generates &'a [u8] and borrows input payload rather than allocating an owned Rust String. The schema still treats those bytes as UTF-8 string content; the unchecked path assumes the input is valid UTF-8 even though the Rust slice type does not prove it. This mode cannot directly borrow the decompressed bytes from compressed frames. Copying a borrowed slice into application storage remains an application-level cost, not a free operation.


binary_opt=guard — UTF-8 view


Generates Utf8Guard<'a>, a borrowed byte-slice view, not an owning arena or automatic copied buffer. from_str is allocation-free; try_from_bytes validates UTF-8 once; from_bytes_unchecked requires caller invariants. as_str, as_bytes and Deref<Target=str> provide typed access. read_guard_checked and trusted read_guard are fundamentally different benchmark operations.


binary_opt=inline — owned inline bytes


For str(0..MAX) with MAX≤65535, generates InlineString<MAX>, keeping the UTF-8 bytes and u16 byte length inside one Rust object. No separate String allocation is needed. However, returning an inline value of capacity 4096 by value can move much more data than the actual string uses; deserialize_into can decode directly into caller-owned final storage.


decompress=true — QSL-LZ


For a bounded dynamic string, generates InlineString<MAX> with deterministic QSL-LZ v1 encoding and no heap scratch. Compression is selected only if the complete compressed frame beats raw payload; otherwise raw mode is used. Compression cannot reduce every possible input, and it can cost more CPU cycles than it saves bytes. Fixed str(N) always generates [u8;N]; fixed compression revision 2 uses either exactly N raw bytes with no header, or 0xFF + length + tokens, never exceeding N bytes. Peers must use matching fixed codec revision.


Fixed str(N) and mixed schemas


str(1024) is [u8;1024] independent of binary_opt modes. There is no dynamic length in its raw representation. A numeric field alongside a String does not imply automatic compression of the whole record; QSL applies string compression only to explicitly marked string fields. compact ranks numbers separately. Bounded strings count UTF-8 bytes, not characters.


6. Detailed schema walkthroughs


Fixed — literal byte offsets


&Fixed { u32 id|default=1|; u64 created_at; u16 checksum; }



Generated struct Fixed { id:u32, created_at:u64, checksum:u16 } implements Serializable, including get_size()=14, serialized_size()=14, serialize_unsafe, deserialize_unsafe and companion methods. The fixed flat writer uses little-endian unaligned stores at literal offsets 0/4/12. Rust struct padding is not serialized. The runtime bottleneck moves from schema interpretation to memory writes and subsequent transfer.


Dense[compact] — static rank masks


&Dense[compact] { u8(0..7) flags; u8(0..31) rank; u16(0..1023) code; }



Three constrained fields occupy 3+5+10 = 18 bits → 3 wire bytes. The generator emits constant masks/shifts and compact methods. The size reduction does not mean latency always improves; unpacking and alignment still incur instruction costs.


Packet / Tagged — presence overhead


&Packet { u64 sequence|default=0|; u16? priority; }
&Tagged { u32 id; u16? a; u8? b; }



Packet has one presence bit rounded to a byte in noncompact layout, followed by its required u64 and optionally u16. Tagged has count and assigned optional tags. When numeric payloads are tiny, metadata and conditional code can dominate the work. The indexed opt_table alternative trades a larger directory for direct access with many optional fields.


SeqNumber[predict_seq] — one dependent tail


&SeqNumber[predict_seq] { u64 id; u32? extra|default=7|; }



Wire size is 8 or 12 bytes. The length-aware read method determines optional presence from cursor position; missing fields decode as None, regardless of the default initializer. A nine-to-eleven-byte message is invalid and must not be passed to the unchecked decoder.


TableFields[opt_table] — offset directory


&TableFields[opt_table] {
    u64 id; u32? a;
    str?(0..100) text|decompress=true|;
    u16? b;
}



First, required id; next a directory with count three and three u32 offsets; finally the present optional payloads. An offset of zero means absent. Generated fields remain Option<T>; OptionalOffsets verifies metadata, not the string codecs. Table cost can outweigh its advantage for a small K when every field is decoded sequentially.


ByteView, GuardView, StringView, InlineView, PackedView


These five supplied demo schemas use the same 0..4096 UTF-8 byte range but produce different Rust ownership modes. StringView owns String; ByteView borrows &[u8]; GuardView borrows Utf8Guard; InlineView owns InlineString<4096>; PackedView owns InlineString<4096> and enables QSL-LZ framing. Benchmarks must distinguish full strings of 1024 Unicode scalar values from a rotation across 1024 short strings; actual byte size is 1024/2048/4096 across character categories.


Token — manually implemented custom type


#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Token(pub u16);
impl qsl::QslCustom for Token {
    const SIZE: usize = 2;
    unsafe fn qsl_write_unchecked(&self, to: *mut u8) {
        std::ptr::write_unaligned(to.cast::<u16>(), self.0.to_le());
    }
    unsafe fn qsl_read_unchecked(from: *const u8) -> Self {
        Self(u16::from_le(std::ptr::read_unaligned(from.cast::<u16>())))
    }
}



This exact type occurs in qsl-demo/src/main.rs, used by CustomPacket[safety] and CompactCustom[compact]. SIZE/COMP_SIZE must match wire bytes; pointer validity, alignment and little-endian representation are part of the unsafe contract. Incorrect invariants can cause undefined behavior.


7. Custom codecs — contract, speed and planned macro


QslCustom is a compile-time-sized trait, not a dynamically dispatched object. Required SIZE, qsl_write_unchecked and qsl_read_unchecked provide the normal path. COMP_SIZE, qsl_comp_write_unchecked, and qsl_comp_read_unchecked have defaults; qsl_size and qsl_comp_size expose constant sizes. The generator can inline hooks, but cannot eliminate validation that users write inside them.


Potential slowdowns: extra range checks, missed inlining, temporary struct copies, endian transforms, variable internal arrays, and indirect helper calls. The provided Criterion export does not contain a direct quantitative experiment proving that all custom codecs are slower than generated ones; any such claim requires a controlled comparison of equal values and equal validation guarantees.


Constraints: fixed SIZE and accurately described compact size, valid input and output pointers, and known advancement rules. predict_seq forbids a zero-byte optional custom codec. The generator rejects some variable custom arrays whose pointer advancement cannot be fixed at build time. A native transmute fast path would require separate bit validity, padding, ABI, endianness and alignment guarantees; no universal transmute codec is implemented here.


Planned: a structure macro to generate QslCustom glue and eliminate hand-written boilerplate. Its exact public syntax and implementation are not present in the uploaded source set. It should not be documented as released or benchmarked until a macro and measured comparisons are available.


8. Buffers, direct storage and sockets


serialize() allocates a single output buffer (Vec<u8> or SerOut under the native feature). unsafe serialize_to() writes into caller-provided storage without independently verifying capacity. SerOut::with_capacity_aligned(capacity,alignment) offers reusable aligned native storage; clear() preserves capacity. deserialize_into(ptr,len,out_ptr) can decode inline fields in the final allocation instead of returning a full maximum-sized object by value.


RawSocket is binary framed TCP, not a raw IP socket. Each frame is [length:u32 LE][QSL bytes]. receive(&mut storage) bounds and reads a frame into caller memory; send_record encodes directly after its prefix; TCP_NODELAY is enabled. Frame validation is not full schema/UTF-8 validation. The k6 WebSocket campaign and RawSocket TCP are separate paths and should not be conflated.

11. Implemented vs planned vs unsafe contracts


Implemented in supplied sources: QSL/DEQ parsing, QslInterpreter, compact/alignment/lifetime/bitmap, predict_seq, opt_table, binary_opt, decompress, QslCustom, OptionalOffsets, Utf8Guard, InlineString, native SerOut, RawSocket and diagnostics helpers.


Not identical to implemented functionality: safety is currently only a parsed flag in the inspected code; the proposed QslCustom structure macro is not present; the thread-local region distribution and atomic cluster with the R occupancy bitmask remain architectural proposals, not active Rust APIs.


Precise ownership note: supplied Utf8Guard borrows a byte slice; it does not own a copied arena. If a future owning guard or region layout is added, it requires separate lifetime rules, tests and API documentation.
