QSL / RUST / MAIN

Обмен заранее описанными данными

QSL анализирует схему при сборке и генерирует конкретные Rust-структуры и кодеки. Типы, границы, порядок полей и выбор памяти задаются явно. Во время обмена готовый код читает и записывает байты.

Rust 1.98+MITRU / ENТекущая ветка: qsl-core

Подходит для согласованных внутренних протоколов, телеметрии и повторяемых записей. Приложение отвечает за транспорт, TLS и согласование версий.

Одна схема, разделённые обязанности

01 / ARCHITECTURE

Общие контракты и исполнение вынесены в qsl-core. Lexer собирает и проверяет схемы, interpreter генерирует Rust. Фасад qsl сохраняет пути ::qsl в готовом коде.

qsl-coreТипы, ошибки, I/O, строки, буферыqsl-lexerQSL / DEQ → проверенные схемыqsl-interpreterСхемы → исходный Rust-кодqslФасад приложения и совместимые пути

Схема

&Message[safety,opt_table] {
    u32 id;
    str(1..255) text;
    u16? code;
}

Обязательные поля всегда стоят перед опциональными. Атрибуты выбираются отдельно.

Генерация при сборке

use qsl_interpreter::prelude::*;
let builder = build_qsl_schem("schemas")?;
let rust = builder.use_interpreter()?;

Сборщик сохраняет схемы. В будущем другой backend сможет использовать тот же контракт SchemaBackend; LLVM пока не реализован.

UTF-8: тип, память и режим чтения

02 / STORAGE

Переменные строки представлены только String, &str, StackString и InlineString. New/reuse — режим работы с назначением. Guard и байтовый срез не являются отдельными строковыми реализациями QSL.

План хранения · x86-64

Rust-типString
Объект24 B
Полезные байты255 B

Это модель раскладки по объявленной ёмкости, не измерение RSS. Ёмкость String может быть больше фактической длины; накладные расходы аллокатора сюда не входят. Окончательный ABI определяет rustc.

По умолчанию STACK_LIMIT = 256 B. Превышение лимита переводит обычные inline-строки в String. Для нативного фиксированного поля сохраняется [u8; N]; заимствованная строка требует живого исходного кадра.

BM, predict_seq и opt_table

03 / OPTIONAL
BM

Присутствие

Маска только опциональных полей. Ширина 8–128 бит выбирается при анализе; обход читает установленные биты.

PS

Индекс по длине

predict_seq использует длину payload для допустимых последовательностей. При BM этот механизм не применяется.

OT

Выбор читателя

opt_table связывает проверенный маркер с функцией чтения. Сохраняет формат и сочетается с BM или PS.

&Packet[safety,optionals=bitmap,opt_table] {
    u8 id;   // 9
    u16? a;  // 0x1234
    u8? b;   // 7
}

Маркер a = 1 находится в старшем бите. Чтение trailing_zeros даёт порядок b → a; writer использует тот же порядок.

Маска11000000
Маркеры2 → 1
ЧитателиOT[1] → OT[0]
C009073412

Синий байт — метаданные. Это модель конкретного формата, проверенная в Rust; она не симулирует время исполнения.

QPS — отдельная обратимая упаковка чисел по операндам и диапазонам. Она не предсказывает наличие optional-полей. Сжатие UTF-8 через decompress=true использует самостоятельный кодек.

Свежие измерения строк

04 / CRITERION

Девять сравнений чтения: new/reuse и &str. Основной набор содержит 1024 символа кириллицы = 2048 полезных байт. Контроль String использует 255 ASCII-символов = 255 байт.

P = M / T · M — исходные полезные байты; T — наносекунды на одну строку.

Замеры при фоновой нагрузке; строгим подтверждением скорости не считаются. Средняя оценка фона за прогон: 8.2%.

Windows 11 x86-64 · i5-7400 · 24 GiB, 2133 MHz · 15 s прогрева · 10 s измерения · 200 выборок · 99% CI · одно ядро · лимит 8 GiB. Unchecked-чтение предварительно проверенных кадров; проверки и подготовка вне таймера. STACK_LIMIT=2048 задан явно. P для &str — логический индекс, байты текста не копируются.
