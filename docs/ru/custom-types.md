# Пользовательские типы QSL: полный технический контракт

**Источник:** `qsl/src/types.rs::QslCustom`, `qsl/src/interpreter.rs`, `qsl-demo/src/main.rs`, `qsl-demo/schemas/custom.qsl`. **Текущий статус:** ручной `QslCustom` реализован; структура-макрос находится в разработке, исходник макроса в предоставленном проекте отсутствует.

## 1. Когда нужен QslCustom

Базовые типы `u8/u16/u32/u64`, ограниченные ранги, фиксированные байтовые строки и поддерживаемые массивы известны генератору. Custom codec используется, если внешний Rust-тип должен занимать конкретное число wire-байтов, а его логика записи/чтения известна разработчику. Это не runtime-плагин: тип определяется во время компиляции, и кодогенератор может встроить его хуки.

## 2. Минимальный контракт

```rust
pub trait QslCustom: Sized {
    const SIZE: usize;
    const COMP_SIZE: usize = Self::SIZE;

    unsafe fn qsl_write_unchecked(&self, to: *mut u8);
    unsafe fn qsl_read_unchecked(from: *const u8) -> Self;

    fn qsl_size(&self) -> usize { Self::SIZE }
    fn qsl_comp_size(&self) -> usize { Self::COMP_SIZE }
    unsafe fn qsl_comp_write_unchecked(&self, to: *mut u8) {
        self.qsl_write_unchecked(to)
    }
    unsafe fn qsl_comp_read_unchecked(from: *const u8) -> Self {
        Self::qsl_read_unchecked(from)
    }
}
```

`SIZE` — точное число записываемых/читаемых байтов стандартного wire codec. `COMP_SIZE` — точное число в compact codec. Если компактное представление действительно отличается, переопредели обе операции; значение `COMP_SIZE` без изменения хуков само по себе не преобразует данные.

## 3. Фактический пример Token

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Token(pub u16);
impl qsl::QslCustom for Token {
    const SIZE: usize = 2;
    #[inline(always)]
    unsafe fn qsl_write_unchecked(&self, to: *mut u8) {
        std::ptr::write_unaligned(to.cast::<u16>(), self.0.to_le());
    }
    #[inline(always)]
    unsafe fn qsl_read_unchecked(from: *const u8) -> Self {
        Self(u16::from_le(std::ptr::read_unaligned(from.cast::<u16>())))
    }
}
```

```qsl
&CustomPacket[safety] { Token code; }
&CompactCustom[compact] { Token code; }
```

Это прямое копирование двухбайтового значения с заданным порядком байтов, а не `transmute` произвольной Rust-структуры. `Token` не содержит padding, указателей или недопустимых битовых комбинаций. **Важная граница:** `[safety]` в предоставленном генераторе не запускает проверку каждого поля.

## 4. Что генерирует QslInterpreter

Генератор использует константы `QslCustom::SIZE` / `COMP_SIZE` для вычисления фиксированных смещений и размеров. При чтении вызывается `Type::qsl_read_unchecked(reader.read_exact(<Type as QslCustom>::SIZE))`, при записи соответствующий raw-pointer hook; компилятор может встроить его. При невозможности определить продвижение указателя в runtime (некоторые переменные массивы пользовательских типов) генератор отклоняет схему. Для `predict_seq` опциональный пользовательский тип обязан иметь `SIZE > 0`, поскольку EOF не различает `None` и присутствующий пустой codec.

## 5. Инварианты `unsafe`

1. `to` указывает как минимум на `SIZE` эксклюзивно доступных для записи байтов, `from` — на `SIZE` доступных для чтения байтов.
2. Запись и чтение обрабатывают **ровно** заявленное число байтов; отсутствуют скрытые динамические хвосты.
3. Исходные и целевые регионы не нарушают контракт перекрывающейся памяти используемых pointer операций.
4. Все возвращённые значения имеют допустимое Rust bit representation. Нельзя создавать ссылки, bool, enum, nonzero-типы и другие значения из непроверенных произвольных битов.
5. Если кодек использует native endian или layout, совместимость между платформами должна быть отдельно ограничена. `repr(C)` не устраняет padding и не делает структуру безопасной для прямой сериализации всех байтов.
6. Буфер полностью валиден **до** unchecked-вызова. Ни `RawSocket`, ни схема `[safety]` не доказывают этот контракт.

## 6. Почему кастомный codec иногда проигрывает генератору

Для встроенного `u64` QSL знает ширину, смещение, little-endian и может выпустить literal pointer store. В пользовательском хуке возможны дополнительные проверки, копирования, преобразования типов, вызовы подфункций, рост регистрового давления, пропущенный inline и условные переходы. Если внутри `QslCustom` вызывается проверяющая функция, `unsafe` у внешнего метода **не отменяет** её стоимость.

В загруженном `all-estimates.csv` **нет отдельной серии, сравнивающей пользовательский custom codec с автоматически генерируемым эквивалентом при равных гарантиях**. Поэтому нельзя честно написать, что custom «доказанно медленнее на X%». Для проверки потребуются два эквивалентных wire-layout, одинаковые буферы, равная безопасность, Criterion и дизассемблирование.

## 7. Предлагаемый структура-макрос (не реализован)

Требования для будущего макроса: вычислять `SIZE` и `COMP_SIZE` из полей, запрещать скрытый padding и ссылочные типы при transmute-пути, генерировать прямые little-endian load/store, проверять допустимость bit representation и поддерживать отдельно trusted и checked API. **Синтаксис самого макроса не установлен исходниками**, поэтому примеры `#[derive(...)]` для него пока нельзя выдавать как существующий способ вызова.

## 8. Бенчмарк-план

Измерять отдельно: прямой generated `Fixed`, ручной `Token`, будущий macro-generated `Token`, варианты с проверками и без них; фиксировать cycles/instructions, p50/p99, кодовые размеры, регрессии после инлайнинга, throughput на массиве записей. Проверка wire-эквивалентности должна проходить **до** измерений. Случаи с невалидными байтами тестировать только через checked validator, не отправлять произвольные fuzz-данные в unchecked decoder.
