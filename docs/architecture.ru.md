# Архитектура компилятора: один сборщик схем, независимые генераторы

Контракт qsl 0.2.0: qsl-lexer 0.2.0 и qsl-interpreter 0.2.0.

| Крейт | Ответственность | Зависимости внутри QSL |
| --- | --- | --- |
| qsl-lexer | Токены, разбор QSL/DEQ, раскрытие шаблонов, общая модель и анализ схем | нет |
| qsl-interpreter | Выбор хранения для Rust и генерация Rust-кода | qsl-lexer |
| qsl | Runtime, проверяемые и доверенные методы, нативные регионы, совместимые импорты компилятора | оба крейта компилятора, qsl-macros-impl |
| qsl-llvm — планируется | Преобразование общей модели в LLVM и компиляция | qsl-lexer; остальные зависимости ещё не выбраны |

## Сбор схем и выбор генератора

Идея QslSchemaBuilder из прототипа перенесена на действующий парсер и настройки dev-qsl. Схемами владеет один сборщик. `build_qsl_schem(path)` возвращает проверенную коллекцию, не выбирая генератор и не записывая результат. Коллекция хранит схемы и настройки DEQ; доступ к ним неизменяемый. AnalyzedModule — другое имя того же типа, а не дополнительное хранилище.

```rust,ignore
use qsl_interpreter::prelude::*;
let builder = build_qsl_schem("schemas")?;
let rust = builder.use_interpreter()?;
std::fs::write(output.join("qsl_gen.rs"), rust)?;
```

Для текста используется QslSchemaBuilder::from_source, для явного списка файлов — from_files / from_files_with_rust. При сканировании каталога непосредственные QSL/DEQ-файлы сортируются по пути; в явных списках сохраняется порядок вызова. Повторные определения, конфликтующие настройки и ошибки схем возвращаются как ошибки. Пути к Rust-шаблонам задаются явно.

## Контракт генератора

Трейт SchemaBackend задаёт типы Output и Error и метод compile(&mut self, &QslSchemaBuilder). Метод use_backend вызывает конкретную реализацию при сборке. RustGenerator реализует этот трейт и возвращает байты Rust-кода. Трейт расширения InterpreterBuilderExt добавляет use_interpreter() и совместимый вариант написания use_interpenter().

Генератор заимствует сборщик, а решения по хранению принимает на копии схем. Исходные данные через публичный интерфейс не изменяются. Один сборщик можно передать нескольким генераторам или использовать после ошибки конкретного генератора. В горячем пути готового кода выбор генератора, вызовы этих трейтов и разбор схем отсутствуют.

## Граница будущего LLVM-компилятора

Будущий qsl-llvm сможет реализовать SchemaBackend и добавить use_llvm() своим трейтом расширения. Ему потребуется определить целевую архитектуру, размещение данных, ABI, инструкции, вывод объектного кода/JIT и связь с runtime. Сейчас LLVM-компилятор и его зависимости не добавлены.

Общая модель сохраняет объявленный порядок полей, диапазоны, кодеки, квантование и механики опциональных полей до выбора Rust-хранения. PreparedModule описывает подготовку именно для Rust. В модели пока сохраняются Rust-аннотации и вспомогательные функции совместимости. Пользовательские Rust-кодеки и предположения о нативном размещении не становятся переносимыми автоматически: другой генератор должен явно поддержать их либо вернуть ошибку. Общий анализ проверяет действующие контракты языка QSL; произвольная совместимость ABI между целевыми архитектурами не заявляется.

## Совместимость и проверка

Фасад qsl сохраняет импорты и проверяемые/непроверяемые runtime-методы. Прежние build_qsl_files используют новый сборщик и выбирают генерацию Rust. Сгенерированный код по-прежнему обращается к ::qsl. Фактические операции чтения, записи и работы с памятью остаются в runtime.

В compiler-pipeline зависимость сборки — qsl-interpreter, зависимость приложения — qsl. Пример проверяет сборщик, DEQ-настройки, обратное чтение и отказ на обрезанном кадре. Тесты проверяют повторное использование сборщика, изоляцию ошибки генератора и неизменность сгенерированного кода. Новые заявления о быстродействии и массовые бенчмарки к этому рефакторингу не добавляются.

## Понижение и диспетчеризация 0.2.0

`qsl-lexer/src/bitmap.rs` рассчитывает число optional-полей, ширину маски и границы маркеров. `regions.rs` создаёт для каждого native-региона самостоятельную схему и одно типизированное поле родителя, сохраняя его обычные теги. `rust_macro.rs`/`schema_macro.rs` раскрывают Rust-шаблоны и сохраняют явно выбранные native-определения. Имена и layout проверяются до генерации Rust.

`qsl-interpreter/src/codegen_optional.rs` формирует курсорные циклы обычного заголовка и BM. Match и статическая OT используют одни unchecked-обработчики полей; checked-материализация имеет отдельные обработчики с Result. `codegen_qps.rs` сохраняет граф PS/OT. При BM эффективный PS выключен: порядок определяет только маска. `codegen_native.rs` создаёт адаптеры кодека/NativeField и проверяемое представление региона.

`QslSchemaBuilder::with_primitive` регистрирует явный контракт QslPrimitive перед проверкой парсера; импорт Rust-шаблонов повторно применяет метаданные. qsl_primitive! создаёт значения обычным Rust-конструктором и использует фиксированный побайтовый ранг для compact. Произвольный QslCustom автоматически не превращается во встроенное число. ABI дополнительно проверяется константными утверждениями компилятора целевого приложения.

В runtime больше нет Windows native-модуля и Windows-зависимости. SerOut использует Rust-аллокатор, RawSocket — std TCP. Выбор хранения, регистровое чтение, COPY и LIFETIME не требуют удалённой Cargo-feature. IPC/TLS приложения и будущий LLVM-backend остаются отдельными задачами.

## Выпуск и воспроизводимость

qsl, qsl-lexer и qsl-interpreter имеют версию 0.2.0. Неизменённый qsl-macros-impl остаётся 0.1.0. BM v2 меняет wire-формат, обычный default/tag-заголовок сохраняется. [Переход](migration-0.2.0.ru.md), [безопасность](safety.ru.md), [индекс исходного API](API.ru.md). Прогон Criterion от 7 ноября не принят как строгий, поэтому выпуск не заявляет измеренного ускорения.

Блокировка RT использует std::sync::Mutex/Condvar; получение слота сохраняет атомарный счётчик. Прямых kernel32/syscall-привязок в QSL больше нет.
