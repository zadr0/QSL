# QSL: модернизация десериализации

Контракт реализации, 6 ноября 2026. [English](MODERNIZATION.en.md).

## Назначение и границы

QSL переносит анализ заранее согласованного бинарного формата на этап сборки. Схема задаёт порядок полей, диапазоны значений и длины. Генератор создаёт конкретный Rust-код; runtime не выбирает схему заново. Все атрибуты включаются явно. Обязательные поля всегда предшествуют опциональным, в том числе после раскрытия Rust-шаблонов.

Изменение представления в памяти не означает изменение wire-формата. Размер кадра, `size_of::<T>()`, ёмкость выходного буфера и пик памяти процесса — разные величины. Показанный линтером размер объекта не равен размеру кадра стека функции: компилятор может создавать временные значения и менять способ передачи результата.

## Конфигурация и строгий STACK_LIMIT

```text
!config STACK_LIMIT = 256;
!config MAX_DATA_SIZE = 65535;
!config QSL_RT = true;
!config QSL_RT_DEFAULT = 16;
!config USE_HASH = xxHash;
```

`STACK_LIMIT` ограничивает максимальное количество **байтов данных каждого встроенного буфера**, а не сумму всех полей схемы. Дескриптор длины и выравнивание дополнительно входят в размер Rust-объекта. Допускается нулевой лимит; конфигурация не меняет wire-идентичность.

Предел строгий: распространяется на автоматическое `aggressive`, явные `binary_opt=inline`, `decompress=true`, фиксированные строки и массивы. Выше лимита COPY использует `String`/`Vec<T>`, сохраняя кодек строки и числовую ширину элементов массива. В нативном Transmutate фиксированное представление нельзя молча заменить дескриптором: генератор выдаёт ошибку и требует явно увеличить лимит. В LIFETIME сырые строки заимствуются независимо от лимита; сжатые строки не могут напрямую ссылаться на сжатые байты и требуют COPY.

## Владение, инициализация и длины

| Ситуация | Представление |
|---|---|
| Обычная переменная строка COPY | `String` |
| Ограниченная COPY + aggressive в пределах лимита | `StackString<N>` |
| Явный inline/LZ в пределах лимита | `InlineString<N>` |
| Фиксированная строка в пределах лимита | `[u8; N]` |
| Строка выше лимита COPY | `String`, прежний wire-кодек |
| Сырая строка LIFETIME / binary_opt=view | `&str` непосредственно из входа |
| Ограниченный числовой массив aggressive | `InlineArray<T, N>` при доказанной ёмкости |
| Фиксированный совместимый массив в пределах лимита | `[T; N]` |
| Массив выше лимита COPY | `Vec<T>` |

Длины строк задаются **байтами UTF-8**, не числом Unicode-символов. Массив задаёт число элементов; лимит переводится в байты с учётом ширины элемента. Длина встроенного буфера — `u32`. Только префикс `0..len` инициализирован и доступен для чтения; остаток `MaybeUninit` не зануляется. `InlineArray<T,N>` уничтожает только инициализированные элементы. Полный `[T;N]` получается лишь после заполнения всех N элементов.

Новые сгенерированные строки не содержат `Utf8Guard`/`Utf8CopyGuard`. `binary_opt=guard` сохранён как совместимый синтаксис COPY, `binary_opt=view` создаёт прямой `&str`. Старые runtime-типы оставлены для ранее написанного кода; это не новый путь генератора. QSL-LZ остаётся отдельным без потерь кодеком с raw-веткой, когда сжатие невыгодно.

## Регистровое чтение

Последовательные обязательные числовые поля группируются автоматически. Полезные байты разбиваются по 16; последний контейнер выбирается по ближайшей ширине 8/16/32/64/128 бит. Например, 25 полезных байтов читаются как 16 + 9: второй логический 128-битный контейнер содержит ровно 9 входных байтов и локальные нули выше них. `u128` не означает один аппаратный регистр x86-64.

Содержимое переменных строк и массивов завершает группу. Генератор может присоединить фиксированный дескриптор длины сырой строки: `u64` + однобайтовая длина дают точное чтение 9 B. Чтение не требует доступности 16 B. Обычные опциональные значения с неизвестным смещением не объединяются в такую группу. В смешанных режимах статические таблицы по-прежнему отвечают за состояние и читателя.

Раскладка линтера показывает `readBytes`, `registerBits` и присоединённые метаданные. Неизвестное абсолютное смещение остаётся неизвестным после динамического поля. Анализатор рекомендует перенос фиксированных обязательных полей перед переменными; такой перенос меняет формат и выполняется только разработчиком.

## Safety: один проход до публикации

```qsl
&Packet[safety,aggressive] {
    u64 id;
    str(1..100) text;
    u32? status;
}
```

Без `[safety]` checked-десериализация не генерируется. `validate`, проверка значений и checked-сериализация остаются средствами явного контроля. Для внешнего входа схема должна включать `[safety]`.

`deserialize_checked` проверяет минимальную длину, затем курсор одновременно читает значения и проверяет их. Проверяются доступные байты, диапазоны чисел, длины, UTF-8, теги, допустимость событий `predict_seq` и окончание кадра. Нет полного предварительного обхода с последующим повторным чтением обычной COPY-схемы. Результат публикуется только после успешного завершения. `deserialize_checked_into` оставляет переданное неинициализированное хранилище без опубликованного результата при ошибке.

`MAX_DATA_SIZE` ограничивает входной кадр и суммарные полезные данные до выделения памяти. В смешанном QPS бюджет числового префикса вычитается до выделения хвоста; метаданные не считаются вторично полезными данными. Переполнение арифметики и ошибка выделения возвращают `QslError`. Распаковка LZ проверяет выходной бюджет до увеличения буфера.

Trusted `deserialize_into` не проверяет произвольные байты. Предусловия: полный корректный кадр согласованной схемы, достаточная инициализированная входная область, выровненное эксклюзивное место результата, отсутствие перекрытия и корректное уничтожение предыдущего значения. Для подготовленного повторного использования действуют дополнительные условия соответствующего destination API. Атрибут inline не отменяет эти требования.

## COPY и LIFETIME Transmutate

`[transmutate,safety]` возвращает собственный объект. При полном совпадении нативного и wire-layout байты копируются в выровненный `MaybeUninit<Self>`, проверяются, затем вызывается `assume_init`. `NATIVE_WIRE_COMPATIBLE` вычисляет смещения и размер средствами целевого rustc, а не предположением о платформе генератора. При несовпадении COPY собирает проверенные поля по их нативным местам.

`[transmutate,lifetime,safety]` предоставляет `deserialize_overlay` и `deserialize_checked`, возвращающие `&Self` непосредственно в исходный кадр. Проверки размера, смещений, little-endian, выравнивания и значений завершаются **до** создания ссылки. Несовместимый layout отклоняется при генерации/компиляции либо проверкой API. Источник остаётся неизменным и живёт дольше ссылки. Обычный `Serializable` остаётся интерфейсом собственного значения; для наложения следует вызывать overlay API явно.

Полное наложение допускает только фиксированные обязательные поля с известным совместимым представлением. COMPACT, QPS, динамические поля и optional несовместимы с ним. Нативный padding не является полезными данными. Размеры доступны отдельно: `NATIVE_BYTES`, `NATIVE_ALIGNMENT`, `WIRE_MAX_BYTES`.

## Rust-шаблоны и вложенные регионы

```rust
#[qsl::schem_macro(aggressive_transmutate)]
pub struct Meta {
    pub id: u64,
    pub value: u32,
    pub tag: qsl::InlineString<4>,
}
```

Макрос сохраняет Rust-тип, задаёт `repr(C)`, Copy/Clone и проверяемые метаданные листовых полей. В этом режиме `InlineString<4>` становится фиксированным `[u8;4]` с проверкой UTF-8. `repr(packed/Rust/transparent)`, динамические и неподдерживаемые поля не допускаются. Нативные метаданные ограничены 64 листовыми полями.

```qsl
&Target[safety] {
    Meta meta;
    str(1..10) name;
}
```

Поля шаблона раскрываются в `meta_id`, `meta_value`, `meta_tag`; вложенные шаблоны раскрываются рекурсивно. Исходный `Meta` остаётся отдельной Rust-структурой. Источники регистрируются через `build_qsl_files_with_rust`. Циклы, повторные имена и обязательное поле после опционального отклоняются.

Альтернатива: `#region(aggressive_transmutate = "Meta");` перед полями и `#end_region;` после них. Регионы поддерживают вложенность и включают только фиксированные обязательные поля. Методы `region_N_copy()` копируют инициализированные листья в нативные смещения; `region_N_view()` требует совпадения расположения и выравнивания внутри объекта. При Safety `deserialize_region_N_copy(input)` и `_view(input)` принимают **только байты данного региона**, без окружающего кадра. COPY может восстановить нативный padding из плоских листьев; input-view требует полного совпадения размера и смещений. Эти wire-регионные методы поддерживают little-endian. Padding никогда не валидируется через чтение неинициализированной нативной памяти.

## Числовые Option и таблицы

Числовые optional-поля скрыты; используйте `try_new(...)`, `field()` и `set_field(...)`. Если диапазон исключает ноль, автоматически выбирается `Option<NonZero*>`. При aggressive ограниченный диапазон кодируется рангом `value - min + 1`, ноль зарезервирован для None. Выбирается минимальный подходящий тип без расширения исходного представления. Для полного диапазона нескольких чисел отдельные признаки объединяются в минимальную общую маску. `Some(0)` остаётся отличным от None; знаковые диапазоны восстанавливаются точно.

`predict_seq` вычисляет индекс по длине и выбирает допустимую последовательность. `opt_table` выбирает метод-читатель по тегу; отдельный атрибут сохраняет обычные wire-байты. `[predict_seq,opt_table]` сохраняет совместный граф длин и таблицу читателей. Невозможный индекс или неподходящие теги checked-чтение направляет в ошибку. Неоднозначное множество полей нельзя восстановить по одной длине: остаются необходимые метаданные. Статические таблицы и обработчики генерируются при сборке.

## QPS: только самостоятельные числа

`[qps]` означает Q16; доступны Q2/Q4/Q8/Q16 и совместимый синоним `quant`. Числа упаковываются обратимо операндами, строки и массивы **не квантуются**, включая числовые массивы и любые длины. Скалярные числа должны идти перед строками/массивами; нарушение — ошибка. QPS не выполняет предиктование.

В смешанной схеме упаковка применима к числовому префиксу; хвост использует собственные обычные кодеки. При переменной длине упакованного префикса добавляется явная граница 1/2 B, при фиксированной — она известна из схемы. Новое смешанное представление имеет отдельный режим канонической идентичности; обе стороны должны обновляться согласованно. Обычные и прежние скалярные форматы проверены золотыми векторами.

Генерируемое prepared-чтение скалярного QPS больше не требует частного читаемого хвоста: `QUANT_PADDING_BYTES = 0`. Точный wire-размер и размер восстановления Rust-объекта различаются. Несжимаемые диапазоны получают raw fallback. Отсутствие ветвления в исходной формуле не гарантирует отсутствие условного перехода в машинном коде: это проверяется для конкретной специализации отдельно. Общий runtime `ByteQps` остаётся API совместимости для старых клиентов; он не определяет политику квантования новых схем со строками.

## RT, кэш и прогресс

`slots=1..64` выбирает число слотов конкретной схемы; без атрибута действует `QSL_RT_DEFAULT`. При `QSL_RT=true` ограниченная схема получает статический пул. `serialize()` ждёт при исчерпании слотов: Windows WaitOnAddress, поддерживаемые Linux — futex, прочие платформы — совместимый механизм ожидания. Lease удерживает слот до Drop; данные разных активных lease не пересекаются. `try_acquire` остаётся неблокирующим. Не следует удерживать все слоты в одном потоке и синхронно запрашивать ещё один: освобождать их будет некому. Статический пул — память процесса; это не IPC-регион.

Предикат ожидания — количество доступных слотов, без переполняющегося счётчика эпох. Release публикует освобождение перед увеличением доступности и пробуждением. Тесты проверяют ожидание, конкурентную исключительность и возобновление; Lean моделирует только сохранение количества слотов.

`[loyal_cache]` использует доказанную верхнюю границу wire. `cache=N` может задать большую ёмкость, меньшая отклоняется. `serialize_cached(&mut CachedFrame<N>)` проверяет достаточность N при мономорфизации, проверяет значения и пишет без повторного сравнения ёмкости. Проверки входных границ сохраняются. Alignment и служебные поля входят в фактический `size_of::<CachedFrame<N>>()`; `CACHE_BYTES` — ёмкость данных, не полный расход RAM.

## Проверка и переход

В Zed 0.8 доступны RU/EN: ошибки схем и диапазонов, UTF-8-длины констант, inlay размеров и смещений, полевая подсказка, дерево символов, инспектор wire и памяти, регистровые группы, регионы и просмотр Rust-генерации. Нативный анализатор должен собираться из той же версии QSL с `--features rust-macros`. При ошибке в одной схеме остальные корректные схемы остаются доступны; нормальная сборка по-прежнему отвергает ошибочный файл целиком. Анализ внешнего Rust-типа без известных размеров помечается неизвестным, а не выдуманным числом.

После обновления следует перегенерировать код: numeric Option переходят на методы, checked-десериализации нужен safety, большие inline-поля меняют Rust-тип при прежнем wire-кодеке. Новые смешанные QPS-кадры согласуются по хэшу. Исторические результаты и исходники измерений сохраняют прежний контракт и не выдаются за текущие.

Команды проверки и четыре точечных Criterion-случая находятся в `qsl/tests/modernization`, `qsl/tests/optional-modes`, `qsl-bench/modernization`. Прогрев 15 с, измерение 10 с, 200 выборок, доверительный интервал 99%, лимит процесса 8 GiB. Полезный индекс P = M/T использует исходные полезные байты, а не сжатый wire. Замер trusted-чтения не включает валидацию и не доказывает скорость обработки недоверенного входа. Абсолютные результаты и команды прилагаются отдельно.

`proofs/Modernization.lean` содержит проверенные модели границ чтения, инициализированного префикса, рангов, None/Some, ёмкости, границ смешанного кадра и сохранения слотов. Это арифметические доказательства, не формальная верификация всей Rust/LLVM-программы.

## Граница trusted-записи и соседних полей

Методы traits Serializable::serialize и BorrowSerializable::serialize теперь unsafe: вызывающий код гарантирует диапазоны, точные длины и суммарный размер, помещающийся в isize::MAX. Для безопасной записи используется serialize_checked / serialize_checked_to. Сгенерированные RT/QPS serialize() остаются безопасными Result-методами с проверкой значений. Это явное изменение API, а не снятие проверки по атрибуту safety.

region_N_view() дополнительно проверяет, что полный нативный объект вместе с хвостовым padding заканчивается до следующего поля родителя. Совпадение только инициализированных листьев недостаточно: наложение не должно захватывать соседнее поле. COPY по листьям остаётся доступным при несовпадении padding.
