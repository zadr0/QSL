# QSL 0.3.0: qsl-core и строковые представления

QSL 0.3.0 переносит общие контракты в qsl-core 0.1.0 и удаляет устаревшие строковые API. Обновляйте qsl, qsl-lexer и qsl-interpreter согласованно до 0.3.0. Реализация атрибутных макросов остаётся qsl-macros-impl 0.1.0. Wire-формат BM v2 и обычных строк не меняется из-за переноса модулей.

## Разделение крейтов

| Крейт | Ответственность | Зависимости |
|---|---|---|
| qsl-core | Ошибки, модель схемы, общие анализы, I/O, контейнеры UTF-8, валидация, буферы и низкоуровневые кодеки | не зависит от lexer/interpreter |
| qsl-lexer | Лексер, QSL/DEQ-парсер, загрузка, раскрытие шаблонов и сборщик схем | qsl-core |
| qsl-interpreter | Подготовка схемы для Rust и генерация исходного кода | qsl-lexer |
| qsl | Фасад исполнения, макросы и совместимые точки входа | core, lexer, interpreter, macro implementation |

Старые модульные пути содержат только re-export и связанные тесты. Реализация хранится в core в одном экземпляре; тип QslError и контракты I/O едины. В core нет парсера и Rust-генератора. Зависимость будущего LLVM-backend от общей модели не требует исполнения interpreter.

## Строки

| Выбор | Rust-представление | Владение |
|---|---|---|
| обычная строка | String | heap, владеющая |
| aggressive и конечная граница в STACK_LIMIT | StackString<N> | встроенная ёмкость |
| binary_opt=inline в STACK_LIMIT | InlineString<N> | встроенная ёмкость, отдельный заголовок длины |
| binary_opt=view | &str | заимствование исходного UTF-8 |

New создаёт новое назначение. Reuse читает в инициализированное назначение; для String заранее готовится достаточная capacity. Это режимы методов, а не дополнительные строковые типы. binary_opt=guard и binary_opt=true отклоняются; Utf8Guard, Utf8CopyGuard и байтовая строка удалены. Явный &str в Rust-макросе сохраняет соседние String владеющими. Фиксированные нативные байтовые поля сохраняют [u8; N].

STACK_LIMIT по умолчанию равен 256 B. Обычные inline-строки сверх лимита восстанавливаются в String. Изменение лимита задаётся явно. Результат с &str действителен только пока жив и неизменен исходный кадр.

## Безопасность

Проверяемые методы по-прежнему проверяют границы, UTF-8, диапазоны, восстановленную длину сжатой строки и общий бюджет. Unchecked-методы сохранены; вызывающая сторона обеспечивает корректный кадр, время жизни, непересечение и достаточную память. Тесты включают поддельные длины, повреждённый UTF-8, все усечения и смешанное владение.

## Новые измерения

Девять случаев Criterion отделяют String new/reuse, StackString new/reuse, InlineString new/reuse и &str. Основной набор — 1024 символа кириллицы / 2048 полезных байт; контроль — 255 ASCII-символов. Для встроенных контейнеров в этом стенде явно выбран STACK_LIMIT=2048; это не стандартный бюджет. Проверки входа и подготовка буферов выполнены до измерения; new String включает выделение и Drop. 15 s прогрева, 10 s измерения, 200 выборок, 99% CI, ограничение процесса 8 GiB. См. [интерактивный отчёт](index.html#measurements).
