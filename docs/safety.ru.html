QSL

Безопасное чтение и предел данных

English · Руководство · Хэши схем

Каждая сгенерированная схема предоставляет безопасные методы. Атрибут safety больше не требуется и сохранён как совместимое написание. Обычные доверенные указательные методы сохраняют отдельный контракт: внешние байты передаются в checked API.

!config MAX_DATA_SIZE = 65535; // значение по умолчанию, байты
!config USE_HASH = xxHash;    // либо xxHash128

Настройки задаются в DEQ, распространяются на каждую генерируемую схему и сохраняются в Schema::MAX_DATA_SIZE. Допустимы положительные значения до isize::MAX и вычисляемые целочисленные выражения. Повторное объявление, в том числе в разных DEQ-файлах, является ошибкой.

Что ограничивается

ОбластьКогда проверяется
Полный входной кадрДо разбора полей
Восстановленный внутренний кадр QPSПо исходной длине заголовка, до записи в restoration
Суммарный объём значенийЕдиным бюджетом при проходе по полям
Выходной кадр checked-сериализатораДо выдачи результата

Каждая из этих величин должна укладываться в MAX_DATA_SIZE. Это не отдельный лимит на каждую строку: два восстановленных поля по 48 B превышают общий предел 64 B, даже если сжатый кадр занимает меньше 64 B.

Для чисел бюджет учитывает исходную ширину значения; для строк — восстановленные байты UTF-8; для поддержанных массивов u8 — число элементов. Числовая константа, занимающая ноль бит в QPS, всё равно учитывается в исходном объёме. Метаданные ограничены общей длиной кадра. Сложение бюджета заменено проверяемым вычитанием, чтобы сумма не могла переполниться.

MAX_DATA_SIZE ограничивает данные одного сообщения. Он не является ограничителем RSS процесса: служебные объекты Rust, ёмкости InlineString, таблицы и одновременно занятые RT-слоты учитываются при проектировании памяти отдельно.

Один проверяющий проход

  1. ValidationCursor::with_limit проверяет размер кадра и создаёт общий бюджет.
  2. Сгенерированный код в объявленном порядке читает метаданные и поля. Проверяются доступность байтов, числовые диапазоны, длины, UTF-8, padding, optional-теги и корректное окончание.
  3. Для LZ проверяются токены, смещения и восстановленный объём. Используется ограниченная стековая область; куча и промежуточный String для валидации не создаются.
  4. Только после успешного окончания курсора вызывается доверенный указательный декодер, который записывает результат в конечное хранилище.

Проверка не сериализует объект для сравнения, не вычисляет хэш сообщения и не оборачивается в catch_unwind. Значения битовых полей извлекаются нативным little-endian окном до 128 бит, а не циклом по каждому биту. Безопасная проверка и последующее создание результата — разные стадии; это не заявление об одном проходе памяти всего декодирования.

При ошибке в любом поле указательный декодер ещё не запускается. Например, длина строки u32::MAX в коротком кадре отклоняется до создания String. Заголовок QPB3 с исходной длиной 4 GiB отклоняется до изменения restoration при стандартном лимите.

Методы каждой схемы

let mut wire = [0u8; 1024];
let used = value.serialize_checked_to(&mut wire)?;
let input = &wire[..used];

Packet::validate(input)?; // только проверка, без создания объекта
let value = Packet::deserialize_checked(input)?;

let mut output = std::mem::MaybeUninit::<Packet>::uninit();
let value = Packet::deserialize_checked_into(input, &mut output)?;

Каждый вызов deserialize_checked сам выполняет ровно одну проверку схемы; предварительно вызывать validate для него не требуется. Deserialize_checked_into доступен для владеющих и заимствованных типов. У заимствованного результата время жизни связано с исходным кадром либо с регионом восстановления QPS.

serialize_checked_to один раз проверяет значения и достаточность выходной области, затем использует нативный writer. serialize_checked() возвращает Result<Vec<u8>> и использует fallible reserve. Для сжатых строк размер выделяемого выхода оценивается верхней raw-границей; owned-вариант консервативно отклоняет её, если она больше лимита. Подготовленный выход проверяет фактический записанный размер; при этой последней ошибке его байты уже могут измениться.

Общий QPS доступен при [qps] без дополнительного safety: serialize_qps_to и deserialize_qps_into / deserialize_qps. Сначала проверяется внешний размер и исходная длина, затем выполняется восстановление, после него — одна проверка внутренней схемы. Повреждённые токены могут изменить restoration до ошибки; превышение заявленной длины отклоняется до записи.

Ошибки и внешние кодеки

Превышение предела возвращает QslError::SizeLimitExceeded; нехватка выходной ёмкости — BufferTooSmall; неверная длина, домен, UTF-8, padding или конец кадра — соответствующую ошибку QslError. Fallible reserve owned-выхода может вернуть AllocationFailed.

QslCustom должен предоставить qsl_validate для входа и qsl_validate_values для checked-записи. Реализации по умолчанию отклоняют непрозрачный кодек. Его произвольный пользовательский код не становится доказанно безопасным от наличия курсора.

Единое подключение макросов

#[qsl::qsl_macro]
pub struct Meta { pub id: u64 }

#[qsl::schem_macro]
pub struct Trace { pub meta: Meta, pub code: u16 }

Оба атрибута доступны через одну зависимость qsl даже без feature rust-macros. Реализация хранится в qsl/macros; отдельный служебный proc-macro-компонент требуется Rust. Feature rust-macros включает только чтение Rust-исходников генератором через Syn. Для этого по-прежнему явно вызывается build_qsl_files_with_rust; атрибут сам не ищет файлы и не меняет исходную структуру.

Лимит и наличие проверяемого API не меняют байты формата и исключены из строгого и лёгкого хэшей. Разные лимиты могут принять или отклонить один кадр по локальной политике. Версия канонического описания остаётся 1.
