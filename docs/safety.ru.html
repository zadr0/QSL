QSL

Безопасное чтение и пределы данных

Checked-десериализация генерируется только при [safety]. Обычная COPY читает и проверяет значения одним курсором, затем публикует результат. Native COPY/overlay проверяет подготовленное представление до assume_init или создания ссылки. Полный предварительный проход и последующий повторный decode для обычного checked-чтения не требуются.

MAX_DATA_SIZE по умолчанию 65535 B: ограничивает входной кадр и суммарные полезные значения до выделения памяти. У массивов учитывается ширина элементов; LZ проверяет восстановленный объём. STACK_LIMIT по умолчанию 256 B относится ко всем встроенным буферам. Сверх него String/Vec сохраняют wire-кодек.

&Packet[safety] { u32 id; str(1..100) text; }
let bytes = value.serialize_checked()?;
let decoded = Packet::deserialize_checked(&bytes)?;
let mut out = std::mem::MaybeUninit::uninit();
let decoded = Packet::deserialize_checked_into(&bytes, &mut out)?;

Отдельный validate перед deserialize_checked не нужен. На ошибке checked_into не публикует частичный объект. Временные успешно прочитанные owned-поля освобождаются обычным Drop. Отдельный validate может выделять память для большого LZ-буфера восстановления, ограниченного бюджетом; нулевые аллокации для любого валидатора не обещаются.

serialize_checked_to проверяет значения и выходную ёмкость. serialize_checked использует fallible reserve; сжатые строки резервируют raw-верхнюю границу, а MAX_DATA_SIZE проверяется по фактическому кадру. При финальной ошибке размера переданный выход мог уже измениться.

Trusted pointer API сохраняет отдельный unsafe-контракт полного корректного кадра, инициализированной памяти и отсутствия перекрытия. QslCustom обязан валидировать собственные представления и значения; произвольный внешний код не становится доказанно безопасным автоматически.

QPS работает только с самостоятельными числовыми полями. Его generated prepared-чтению больше не нужен частный хвост: QUANT_PADDING_BYTES = 0. Строки, массивы и их длины используют собственный кодек. ByteQps остаётся legacy runtime API, а не новой политикой схемных строк.

Полный контракт, ошибки, native COPY/LIFETIME и миграция.

Trusted trait-методы Serializable::serialize / BorrowSerializable::serialize теперь unsafe. Их предусловия должны выполняться вызывающим кодом. Сгенерированные RT/QPS serialize() остаются безопасными Result-методами с проверкой значений; для общего безопасного выхода используйте serialize_checked.

Атрибут safety не отключает unsafe-чтение. Нативные COPY/LIFETIME и регионы всегда имеют явные методы _unchecked без валидации входа; checked-методы доступны параллельно. Полный перечень и обязанности вызывающего кода: unchecked API.

Длина LZ-блока из входа не задаёт допустимый размер распаковки. Каждый токен проверяется по фактически восстановленным байтам, пределу destination и общему MAX_DATA_SIZE до reserve/записи. Поддельные длины, выход MAX+1, усечённые literal/offset и недопустимые ссылки отклоняются; unchecked API остаётся отдельным.
