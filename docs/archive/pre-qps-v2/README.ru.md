# QSL — DSL бинарной сериализации с генерацией Rust

[Интерактивная документация](docs/index.html) · [Полный технический справочник](docs/architecture.ru.md) · [Индекс Rust API](docs/API.ru.md) · [English](README.en.md)

QSL описывает схему бинарного сообщения как **типы, порядок, ранжированные диапазоны, опциональность, атрибуты строк и модель владения памятью**. Парсер нормализует DSL в `QslSchema` и передаёт генератору `QslInterpreter`. Генератор создаёт Rust-типы и специализированные методы чтения/записи; известные заранее смещения, маски и ширины переводятся в константы.

```qsl
&Fixed { u32 id; u64 created_at; u16 checksum; }
&Dense[compact] { u8(0..7) flags; u8(0..31) rank; u16(0..1023) code; }
&SeqNumber[predict_seq] { u64 id; u32? extra; }
&TableFields[opt_table] { u64 id; u32? a; str?(0..100) text|decompress=true|; u16? b; }
```

Основные технические решения:

- **`compact`** — ранговая упаковка ограниченных целых до `ceil(log₂(MAX−MIN+1))` бит, а не автоматическое сжатие всех данных.
- **`predict_seq`** — один optional-хвост после mandatory, наличие которого выводится по длине валидной записи. Не допускает неполный хвост.
- **`opt_table`** — каталог `1+4K` байт для двух и более optional с прямым обращением по индексу.
- **`binary_opt` / `lifetime`** — owned `String`, borrowed `&[u8]`, `Utf8Guard` или `InlineString` с разными затратами на аллокации, копирование и время жизни.
- **`decompress=true`** — только явно выбранное строковое сжатие QSL-LZ, с raw fallback при невыгодном результате.
- **`QslCustom`** — контракт пользовательского codec с точным фиксированным размером и `unsafe` pointer hooks; кастомный структура-макрос пока разрабатывается.
- **`SerOut`, `serialize_to`, `RawSocket`** — переиспользуемые native buffers и прямой бинарный TCP с префиксом длины.

**Безопасность:** `safety` распознаётся как флаг, однако переданный генератор не включает по нему отдельную полную проверку wire input. Unchecked-декодер требует валидных границ, UTF-8, версий схем и корректных значений; для сетевого ввода нужен отдельный валидирующий этап.

**Производительность:** в [`docs/data/all-estimates.csv`](docs/data/all-estimates.csv) доступны 170 измерений Criterion из нескольких профилей. Они показывают и ускорения, и регрессии. Например, заимствованный Guard не равнозначен `String`, а декодирование в готовую память отличается от возврата большого inline объекта по значению. CPU, кэш, компилятор и входные данные меняют результат.

## Публикация

Скопируй `README.md`, `README.ru.md`, `README.en.md` и `docs/` в корень GitHub-репозитория. Для сайта включи **Settings → Pages → Deploy from a branch → main → /docs**. HTML двуязычный и не требует сборщика или CDN.

Полные методы, правила, примеры и ограничения — в [технической документации](docs/architecture.ru.md) и [индексе API](docs/API.ru.md). В каталоге исходных материалов при подготовке не было `Cargo.toml` основного QSL, поэтому новая компиляция библиотечного проекта здесь не заявляется.

**Примечание к сравнению:** WebSocket smoke-показатели получены на предыдущей реализации строк QSL; последующие `&[u8]`/`Utf8Guard`-оптимизации проверялись отдельно в Criterion, но их end-to-end эффект в этих WebSocket цифрах не измерен. См. [нагрузочные тесты](docs/performance.ru.md).
