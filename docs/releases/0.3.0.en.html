QSL 0.3.0

Shared core and UTF-8 storage

qsl, qsl-lexer and qsl-interpreter are 0.3.0; the new qsl-core starts at 0.1.0. The unchanged procedural implementation remains 0.1.0. Requires Rust 1.98+. MIT licensed.

Shared schema types, errors, configuration, wire analysis, I/O, validation, strings and buffers belong to qsl-core. Core does not depend on the parser or Rust generator. Compatible module paths retain re-exports.

Variable UTF-8 fields use String, &str, StackString and InlineString. Guard and byte-string modes are removed. binary_opt=view returns &str while sibling String fields remain owned. New/reuse are destination modes. STACK_LIMIT defaults to 256 B; larger ordinary inline storage falls back to String. Checked and explicit unsafe methods remain available.

Compatibility and installation

This is a breaking pre-1.0 API change. Module extraction preserves existing ordinary-string and BM v2 wire encodings. Peers must agree on schemas and wire-affecting options.

qsl = "=0.3.0"

Verification and measurements

Verification covers all four packages, generated structures, string ownership, malformed lengths/UTF-8 and an independent registry consumer. Publication records and logs are retained under reference/crates-release-0.3.0. The nine recorded Criterion cases identify their inputs and the measured source snapshot before release-metadata changes. Background CPU of 8.2% prevents accepting that run as strict speed evidence. Publishing this release does not establish a new speedup.
