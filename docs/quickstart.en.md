# QSL: quick start

[Russian](quickstart.ru.md) · [English](quickstart.en.md)

QSL is a data-description language and a generator of specialized Rust binary codecs.
Peers agree on field order, value ranges, lengths and codecs. QSL analyzes the schema
during the Cargo build and emits concrete Rust structures and methods for exchanging bytes.

It targets controlled internal protocols, IPC, telemetry and repeated records with known
layouts. Developers specify memory bounds, ownership and input validation. Applications
provide version negotiation, routing and TLS.

## Quick start

Requires Rust 1.98 or later. Release checks run on Windows 11 x86-64.

Create an application with cargo new qsl-demo, then add the four files below.
Keep the package section generated by Cargo. Use the same QSL version in application
and build dependencies.

### 1. Cargo.toml

```toml
[dependencies]
qsl = "=0.1.2"

[build-dependencies]
qsl = "=0.1.2"
```

### 2. user.qsl

```qsl
&User[safety] {
    u64 id;
    str(1..100) name;
}
```

### 3. build.rs

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let out = std::path::PathBuf::from(std::env::var_os("OUT_DIR").unwrap());
    qsl::build_qsl_files(&["user.qsl"], &[], out)?;
    Ok(())
}
```

### 4. src/main.rs

```rust
include!(concat!(env!("OUT_DIR"), "/qsl_gen.rs"));

fn main() -> qsl::QslResult<()> {
    let user = User {
        id: 42,
        name: "Ada".into(),
    };
    let bytes = user.serialize_checked()?;
    let restored = User::deserialize_checked(&bytes)?;
    assert_eq!((restored.id, restored.name.as_str()), (42, "Ada"));
    println!("{}: {} ({} bytes)", restored.id, restored.name, bytes.len());
    Ok(())
}
```

Run cargo run. Expected output:

```text
42: Ada (15 bytes)
```

The schema describes an owned u64 and a String containing 1–100 UTF-8 bytes.
build.rs generates qsl_gen.rs under OUT_DIR. The application includes the generated
type and calls its checked encoder and decoder.

## Format and safety rules

- Required fields always precede optional fields.
- String bounds count UTF-8 bytes; array bounds count elements.
- safety enables checked deserialization. Explicit unsafe APIs remain available;
  callers guarantee complete valid frames and sufficient, correctly aligned storage.
- Checked reads validate lengths, domains, UTF-8, optional metadata and MAX_DATA_SIZE.
- Each compressed-string run is bounded by the actual restored size before reserve
  or writes. A compressed length header does not prove the decoded size.
- The schema and wire-affecting options define the format. Peers coordinate changes.

## Optional mechanisms

| Mechanism | Purpose |
|---|---|
| aggressive | Bounded inline ownership within STACK_LIMIT |
| qps=Q2/Q4/Q8/Q16 | Lossless scalar numeric packing; qps defaults to Q16 |
| predict_seq | Length-derived optional-state index |
| opt_table | Optional field tag to reader dispatch |
| lifetime | Borrowing supported raw fields |
| decompress=true | Independent QSL-LZ string compression |
| transmutate | Explicit native-layout COPY or overlay |
| QSL_RT | Bounded static output slots for eligible schemas |

Attributes are opt-in. MAX_DATA_SIZE defaults to 65535 useful bytes and also limits
the input frame. STACK_LIMIT defaults to 256 data bytes per inline buffer.
Larger ordinary COPY strings and arrays use String/Vec. Fixed native Transmutate
requires an explicitly sufficient limit.

QPS does not quantize strings, arrays or their lengths. QSL-LZ is a separate codec.
predict_seq and opt_table are independent mechanisms and may be combined.

## Cargo features

| Feature | Purpose |
|---|---|
| rust-macros | Import marked Rust definitions during schema analysis |
| native | Windows native memory and socket support |
| diagnostics | Diagnostic checked cursor APIs |

The attributes qsl::qsl_macro and qsl::schem_macro are re-exported by qsl.
During the 0.1 series, coordinate API and wire choices explicitly.
