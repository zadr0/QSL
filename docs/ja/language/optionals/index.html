オプションフィールド

T? と書いたフィールドはオプションです。フレームは、どのオプションフィールドが存在するかを示す必要があります。QSL にはその方法が 3 つあります。さらに、生成されるリーダーのディスパッチ方法だけを変える opt_table があります。

モード 属性 存在情報の格納方法 デフォルトと同じバイト列
デフォルト なし 存在するフィールドの個数とそのタグ はい
ビットマップ optionals=bitmap オプションフィールドごとに 1 ビットのマスク いいえ
長さインデックス predict_seq ペイロード長から導出 いいえ
リーダーテーブル opt_table 組み合わせたモードと同じ はい

デフォルト：個数とタグ

Section titled “デフォルト：個数とタグ”

属性がない場合、フレームはヘッダで始まります。ヘッダには、存在するオプションフィールドの個数と、存在する各フィールドのタグコードが入ります。その後に必須の値が続き、最後に存在するオプションの値が宣言順に続きます。オプションフィールドが 1 つだけの型は、存在を示すビットを 1 つだけ使います。生成されたリーダーは、タグに対する match でディスパッチします。

ヘッダは最下位ビットから詰めて格納されます。個数は bit_length(optional_count) ビットを使います。各タグコードはフィールドのタグから 1 を引いた値で、bit_length(max_tag - 1) ビットを使います。compact を指定しない場合、ヘッダはバイト単位までパディングされます。

リポジトリの optionals サンプルは、id = 42 と、f0 = 11、f1 = 22、f2 = 33 のうちの一部をエンコードします。

存在するフィールド フレーム
なし 00 2a 00 00 00
f0、f2 36 2a 00 00 00 0b 21
f0、f1、f2 e7 2a 00 00 00 0b 16 21
タグは id が 1、f0〜f2 が 2〜4 なので、各タグコードは 2 ビットを使い、個数も 2 ビットを使います。f0 と f2 の場合、ヘッダには個数 2（10）、続いてコード 1（01）と 3（11）が入り、0b110110 = 36 になります。opt_table がなくても、フレームは同じです。

ビットマップ

Section titled “ビットマップ”

optionals=bitmap は、オプションフィールドだけを対象とするリトルエンディアンのマスクを書き込みます。マスクの幅は、型が持つオプションフィールドの数で決まります。

オプションフィールドの数 0 1〜8 9〜16 17〜32 33〜64 65〜128
マスクのバイト数 0 1 2 4 8 16
最初のオプションフィールドにはマーカー 1 が割り当てられ、最上位ビットに格納されます。リーダーは trailing_zeros で立っているビットを探すため、存在する値はマーカーの降順に書き込まれ、読み取られます。必須の値は宣言順のままです。

フィールドを切り替えると、フレームの変化を確認できます。&P[safety,optionals=bitmap,opt_table]{u8 id;u16? a;u8? b;} で id = 9、a = 0x1234、b = 7 の場合、フレームは c0 09 07 34 12 です。マスク、id、b の順に並び、最後にリトルエンディアンの a が続きます。

[safety] を指定すると、デコーダはマスクを走査する前に、型に存在しないマーカーのビットがマスクで立っていないことを 1 回だけチェックします。

フォーマットの変更

ビットマップ v2（0.2.0 以降）は、すべてのフィールドを対象としていた以前のマスクと互換性がありません。両側のピアを同時にアップグレードしてください。

長さインデックス：predict_seq

Section titled “長さインデックス：predict_seq”

predict_seq を指定すると、デコーダはペイロード長から、どのオプションフィールドが存在するかを割り出します。これが成り立つのは、存在するフィールドのどの組み合わせでも長さが異なる場合だけです。

  • オプションフィールドが 1 つなら、入力の終端で判定できます。
  • 複数のフィールドには、部分和がすべて異なるような固定サイズが必要です。

曖昧な組み合わせと、エンコード結果が 0 バイトになるオプションフィールドは、ビルド時に拒否されます。存在情報を長さから得るため、信頼済み入力用のデコーダにはポインタだけでなく入力長も必要です。

optionals=bitmap が指定されている場合、predict_seq は無視されます。compact との組み合わせはビルドエラーです。

opt_table と組み合わせた predict_seq

Section titled “opt_table と組み合わせた predict_seq”

[predict_seq,opt_table] は、0.2.0 より前に単独の [opt_table] が生成していたフォーマットを維持します。長さグラフが対応するのは、最大 12 フィールド、ペイロード 65535 バイトまでです。12 フィールドを超える場合は、すべてのフィールドが同じ固定幅である必要があり、上限は 64 フィールドです。0.2.0 より前に [opt_table] で書いたフレームがある場合は、両側を [predict_seq,opt_table] に切り替えてください。

リーダーテーブル：opt_table

Section titled “リーダーテーブル：opt_table”

opt_table は match を、読み取り関数の静的テーブルに置き換えます。読み取り関数はオプションフィールドごとに 1 つあり、テーブルはマーカーをインデックスとします。バイト列もスキーマハッシュも変わりません。デフォルトのフォーマット、compact、ビットマップのいずれとも併用できます。

テーブルを介した間接呼び出しが match より速いとは限りません。採用する前に、実際のデータで計測してください。

初期値

Section titled “初期値”

数値フィールドに |default=N| を付けると、そのフィールドを N に設定する impl Default が型に生成されます。オプションフィールドの場合、デフォルト値は Some(N) です。ワイヤフォーマットとスキーマハッシュは変わりません。default=N を参照してください。
