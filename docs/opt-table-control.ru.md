# Контроль: default против opt_table

> Исторический профиль: подпись `opt_table` здесь обозначает прежний смешанный граф длин. Его формат сохраняет `[predict_seq,opt_table]`; новый отдельный `[opt_table]` выбирает читателя по тегу. [Разделение и переход](optional-modes.ru.md).

[English](opt-table-control.en.md) · [Замеры QPS](performance.ru.md)

Один обязательный u32 и N опциональных u64. N = 1, 2, 3, 5, 10; значения, порядок полей и явные атрибуты inline/safety одинаковы в каждой паре. QPS выключен: эффект таблицы рассматривается отдельно от сжатия. В предыдущем профиле QPS другая схема и рабочий набор; абсолютные времена этих групп напрямую не сравниваются.

В этом прогоне opt_table читает медленнее при N=1 и N=5, быстрее при N=2, N=3 и N=10. Запись быстрее при всех пяти размерах. Поэтому opt_table остаётся явным выбором схемы, а не общей рекомендацией для ускорения.

Это разные wire-кодеки для одинаковых логических полей. Размер метаданных default может зависеть от состояния; opt_table может использовать фиксированную область присутствия. Пустой хвост из 10 optional-полей с opt_table занимает больше места, хотя максимальный кадр меньше. Экономия и время не выводятся по одному максимальному размеру.

## Условия

Для каждого размера циклически используются 1024 кадра с масками `(i*405+17)&1023`, усечёнными до N бит. Все 2^N состояний встречаются одинаково часто; ID и значения также меняются. До замера оба формата валидируются; результаты checked- и prepared-чтения сравниваются по всем полям. При равных ширинах optional-полей длина даёт количество, но обычно не идентифицирует разреженное подмножество: это намеренно не только лучший детерминированный случай.

Каждый случай: прогрев 15 s, измерение 10 s, 200 выборок, CI 99%. Измеряются prepared serialize_into / deserialize_into; подготовка, аллокация и валидация исключены, выбор кадра и black_box включены. Wire-буферы ёмкостью 128 B и конечные области выровнены на 64 B; исходные объекты имеют естественное выравнивание Vec. Сборка выполняется до установки лимита 8 GiB для измеряемого процесса.

Peak job commit: 7.89 MiB. Windows 11 x86-64; i5-7400; RAM 24 GiB / 2133 MHz; Rust 1.98 / LLVM 22.1.8; Criterion 0.8.2. Привязка к ядру и изоляция ОС не задавались. Хеши исходников зафиксированы до замера и сверены после него.
