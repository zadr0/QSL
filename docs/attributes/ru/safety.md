# `safety` — спецификация атрибута

**Статус:** реализовано, кроме оговорки для `safety`: только флаг в этой версии.

## Синтаксис

```qsl
&CustomPacket[safety] { Token code; }
```

## Точная механика и wire-эффект

Атрибут распознаётся парсером и сохраняется в FLAG_SAFETY, но просмотренный QslInterpreter не выбирает по нему проверяющий декодер. Checked I/O с feature diagnostics — отдельный механизм.

## Ограничения и недопустимые сочетания

Нельзя считать флаг доказательством безопасности сетевого сообщения. Для unsafe чтения необходимо проверить длины, значения, UTF-8 и схему.

## Контракт исполнения

При изменении схемы обе стороны должны использовать совместимую ревизию формата. Путь `unsafe` не подтверждает корректность произвольного сетевого ввода; источник, объём данных и диапазоны должны соответствовать схеме.

## Что измерять

Сравнивай полную запись и чтение на одних данных, отдельно метаданные и payload; фиксируй размер сообщения, аллокации, CPU, измерительный профиль и p99. Исходный пример замера:
`records/Fixed/read/current` — [all-estimates.csv](../../data/all-estimates.csv).

## Исходная реализация

`qsl/src/parser.rs flag dispatch; io_checked.rs`.
