# `binary_opt` — спецификация атрибута

**Статус:** реализовано, кроме оговорки для `safety`: только флаг в этой версии.

## Синтаксис

```qsl
&ByteView { str(0..4096) text|binary_opt=true|; }
&GuardView { str(0..4096) text|binary_opt=guard|; }
&InlineView { str(0..4096) text|binary_opt=inline|; }
```

## Точная механика и wire-эффект

true генерирует &'a [u8], guard — Utf8Guard<'a> (borrow), inline — InlineString<MAX>. Обычное поле генерирует String. На trusted пути byte view и guard не аллоцируют.

## Ограничения и недопустимые сочетания

Только string/str. Inline требует конечной длины ≤65535, фиксированное str(N) всегда [u8;N]. Нельзя заимствовать декомпрессированные байты без другого хранилища.

## Контракт исполнения

При изменении схемы обе стороны должны использовать совместимую ревизию формата. Путь `unsafe` не подтверждает корректность произвольного сетевого ввода; источник, объём данных и диапазоны должны соответствовать схеме.

## Что измерять

Сравнивай полную запись и чтение на одних данных, отдельно метаданные и payload; фиксируй размер сообщения, аллокации, CPU, измерительный профиль и p99. Исходный пример замера:
`utf8_1024/ascii/read_guard` — [all-estimates.csv](../../data/all-estimates.csv).
