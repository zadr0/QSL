# `predict_seq` — спецификация атрибута

**Статус:** реализовано, кроме оговорки для `safety`: только флаг в этой версии.

## Синтаксис

```qsl
&SeqNumber[predict_seq] { u64 id; u32? extra|default=7|; }
```

## Точная механика и wire-эффект

Отсутствующий хвост: 8 байт id; присутствующий: 8 байт id + 4 байта extra. Нет presence header. Чтение требует cursor/len. Для короткого tail len=9..11 unsafe-чтение может нарушить контракт.

## Ограничения и недопустимые сочетания

Ровно один optional и он последний. Нельзя совместить compact, bitmap или opt_table. Present zero-byte field непредставим. `deserialize_unsafe(ptr)` паникует.

## Контракт исполнения

При изменении схемы обе стороны должны использовать совместимую ревизию формата. Путь `unsafe` не подтверждает корректность произвольного сетевого ввода; источник, объём данных и диапазоны должны соответствовать схеме.

## Что измерять

Сравнивай полную запись и чтение на одних данных, отдельно метаданные и payload; фиксируй размер сообщения, аллокации, CPU, измерительный профиль и p99. Исходный пример замера:
`optional/predict_seq_present_read` — [all-estimates.csv](../../data/all-estimates.csv).

## Исходная реализация

`qsl/src/types.rs validate; interpreter.rs emit_sequential_read/emit_trait`.
