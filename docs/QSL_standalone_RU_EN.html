Суть и инварианты


QSL генерирует специализированный Rust-код для обмена заранее описанными данными. Схема задаёт типы, диапазоны, владение строками и порядок полей. Статический анализ и выбор примитивов выполняются при сборке.


Атрибуты и дополнительные механики опциональны. Порядок обязателен всегда: [обязательные][опциональные]. Теги инкрементальны и назначаются компилятором. Автоматической перестановки данных нет.


QPS — точное сжатие числовых операндов с квантованием. Предиктование по длине выполняет opt_table. QPS не требует опциональных полей.

Сборка


build.rs задаёт пути QSL, DEQ и Rust-шаблонов. Парсер разрешает типизированные константы, строит QslSchema, проверяет диапазоны и порядок. Затем раскрываются Rust-шаблоны, выбираются раскладки и кодеки. QslInterpreter выпускает qsl_gen.rs; Rust компилирует плоские специализированные методы.

Для шаблонов нужен feature rust-macros в normal- и build-зависимости. Без них используется build_qsl_files.


QPS и точная математика


&P[qps=Q16,safety] { u64(0..15) a; u64(0..15) b; }


Схема только с обязательными полями корректна. [qps] выбирает Q16. Q1 не является квантом нового QPS. qps и quant одновременно не задаются.


Для a <= x <= b ранг r=x-a, ширина B=bit_length(b-a). Генератор выбирает:


k = min(log2(Q), B)       d = 1 << k
u = r >> k               v = r & (d - 1)
c = u | (v << (B-k))
r = ((c & ((1 << (B-k))-1)) << k) | (c >> (B-k))
x = a + r


Частное и остаток сохраняются полностью. Это не округление. Для B=0 значение восстанавливается из схемы без payload-битов; генератор отдельно обрабатывает крайние ширины и не делает сдвиг на ширину регистра.


Экономия возникает из ограниченного домена и упаковки, а не из магического уменьшения произвольных данных. Восемь u64(0..15) занимают 4 B payload вместо 64 B. Q2/Q4/Q8/Q16 могут давать одинаковую длину и разные точные байты; проверены отдельные golden vectors.


Неподдерживаемые типы и отсутствие экономии с учётом приватного хвоста дают явный raw fallback. Анализатор показывает QUANT_ACTIVE и причину. Выбор делается на схему. Отдельный короткий кадр не обязан уменьшаться при фиксированных метаданных.


None отличается от Some(константа). Сам QPS не выводит присутствие из длины. Вместе с opt_table используются известные битовые ширины и булевы префиксы; длина сжатого payload не подменяет размер восстановленного объекта.


Буферы и методы


Упакованный кадр и восстановленная структура находятся в разных областях. QPS не уменьшает size_of::<T>(). Подготовленному pointer API нужен инициализированный QUANT_PADDING_BYTES; хвост не передаётся. Checked-чтение точного среза не требует скрытого padding.

let decoded = P::deserialize_checked(frame.as_slice())?;


Raw fallback сохраняет исходный API serialize(). Нельзя считать, что все режимы возвращают один контейнер. deserialize_into пишет в конечную область; для живого значения используется соответствующий reuse API.


opt_table: предиктование


&Packet[opt_table,safety] { i32 id; u8? a; u8? b; }


H — известная метаобласть, B — прочитанная обязательная часть, L — длина optional-payload. I(L)=sum((L > boundary_j) as usize). Границы выводятся из схемы; равнозначные соседние события объединяются. Плотный массив на каждый байт не нужен.


Здесь I=(L>0)+(L>1). При L=0 полей нет; при L=2 присутствуют оба; L=1 требует метаданных для различения a и b. EVENT_TABLE выбирает специализированную функцию. Однозначная функция не читает тег, хотя зарезервированный байт остаётся в кадре. Размеры кадров — 5/6/7 B.


Для str?(3..33) name и str?(1..255) description длина выше 33 гарантирует description, но допускает name. Свыше 255 присутствуют оба. Нативные длины вынесены в метаобласть; последнее переменное поле выводится из остатка. Настоящая неоднозначность требует метаданных.


CRITICAL_POINTS, EVENT_TABLE, OFFSET_TABLE и таблицы чтения размещаются рядом с типом. OFFSET_TABLE содержит рецепты смещений. [opt_table,predict_seq] заменяет косвенный вызов прямыми выражениями, сохраняя wire-байты. Inline — отдельная настройка. Общий бюджет анализа: 12 полей / 65535 B; одинаковые фиксированные ширины поддержаны до 64 полей. Есть явные fallback. [opt_table=legacy] сохраняет прежний каталог в кадре.

Исходные Rust-типы сохраняются вложенными. Только Message получает meta_clock_ticks, meta_kind, id, extra. Дубли типов не выпускаются. QSL-атрибута [macro] нет. Проверяются циклы, коллизии, владение, конечный порядок, 64 поля и глубина 64. Входные файлы задаются явно; произвольные generics, cfg и вычисляемые ёмкости не угадываются.


Валидация, RT и сеть


[safety] генерирует validate, validate_values, deserialize_checked и checked-чтение в конечную область для owned-типов. Проверяются границы, метаданные, диапазоны, UTF-8, LZ и точное окончание. Неверные встроенные данные возвращают QslError до trusted-чтения. Для custom-кодека нужна собственная корректная валидация. Атрибут не добавляет проверок в каждый trusted-вызов.


!config QSL_RT = true;
!config QSL_RT_DEFAULT = 16;


RT выключен по умолчанию. Только конечные схемы получают статические выходные слоты. 16 здесь — число одновременно занятых буферов на схему, а не квант QPS. Исчерпание возвращает ошибку без запасной аллокации. Учитываются padding и бюджет 64 MiB на схему; deserialize_into сохраняется.


Feature native предоставляет Windows NativeRegion, SharedRegion с IPC и прямой блокирующий NativeSocket. Shared-публикация использует release/acquire; между процессами передаются смещения, не абсолютные указатели. TCP framing не заменяет проверку QSL. Эти механизмы не измерялись свежим Criterion-прогоном.


Редактор, совместимость и доказательства


QSL-Extension 0.5: RU/EN, inlay hints, hover поля, дерево, completion, определения, Ctrl+. для раскладки/событий/Rust. QPS не требует optional-хвоста. Rust-макрос раскрывается до точного анализа. Оценки fallback помечены; native bridge сообщает qpsCodecRevision=2. После обновления файлов сервера нужен его перезапуск.


До revision 2 qps означал другой D/index-формат. Для сохранения тех байтов выбирается state_bits. quant=Qn сохраняет прежний числовой operand-формат и является синонимом нового QPS. Схема, конфигурация, границы сообщения и версия входят в соглашение сторон; угадывания формата по len нет. QBProto handshake/R остаётся планом.

Свежие четыре измерения, ASM, стенд и хеши опубликованы отдельно. Основные demo-файлы с намеренно неверным View не исправлялись ради успешной сборки.

Purpose and invariants


QSL generates specialized Rust for exchanging data described in advance. Schemas define types, ranges, string ownership and physical order. Static analysis and primitive selection happen at build time.


Attributes and additional mechanisms are opt-in. Order is always mandatory: [required][optional]. Tags are compiler-assigned incrementally. Data is never silently reordered.


QPS is exact numerical operand compression with quantization. opt_table performs prediction from length. QPS does not require optional fields.

QPS mathematics


&P[qps=Q16,safety] { u64(0..15) a; u64(0..15) b; }


Required-only schemas are valid. [qps] defaults to Q16. Q1 is not a quantum of new QPS. Do not specify both aliases qps and quant.


For a <= x <= b, rank r=x-a, width B=bit_length(b-a):


k = min(log2(Q), B)       d = 1 << k
u = r >> k               v = r & (d - 1)
c = u | (v << (B-k))
r = ((c & ((1 << (B-k))-1)) << k) | (c >> (B-k))
x = a + r


Both quotient and remainder are retained. There is no rounding. B=0 constants restore from the schema without payload bits; code generation separately handles extreme widths and avoids shifts by a register's full width.


Savings come from bounded domains and packing, not from shrinking arbitrary data by arithmetic. Eight u64(0..15) values occupy 4 payload bytes instead of 64. Q2/Q4/Q8/Q16 can have equal lengths but different exact bytes; distinct golden vectors are tested.


Unsupported types and no saving including private padding select explicit raw fallback. Analysis exposes QUANT_ACTIVE and a reason. The decision is per schema. A short individual frame need not shrink when fixed metadata is present.


None differs from Some(constant). QPS alone does not infer presence from length. With opt_table, known bit widths and Boolean prefixes supply offsets; compressed payload length never replaces restored object size.


Buffers and methods


Packed frames and restored objects occupy separate regions. QPS does not reduce size_of::<T>(). Prepared pointer APIs require initialized QUANT_PADDING_BYTES, never transmitted. Exact-slice checked decoding requires no hidden padding.

opt_table prediction


&Packet[opt_table,safety] { i32 id; u8? a; u8? b; }


H is the known metadata span, B the consumed required prefix, L the optional-payload length. I(L)=sum((L > boundary_j) as usize). Boundaries come from the schema; adjacent equivalent events merge. No dense per-byte array is required.


Here I=(L>0)+(L>1). L=0 identifies no optionals; L=2 forces both; L=1 needs metadata to distinguish a and b. EVENT_TABLE selects specialized functions. A deterministic handler skips tag reads although the reserved byte remains on wire. Frames occupy 5/6/7 B.


For str?(3..33) name and str?(1..255) description, lengths above 33 force description while allowing name. Above 255 both are present. Native length words occupy metadata; the last variable field comes from the remainder. Real ambiguity needs metadata.


CRITICAL_POINTS, EVENT_TABLE, OFFSET_TABLE and reader tables sit beside the type. OFFSET_TABLE stores recipes. [opt_table,predict_seq] replaces the indirect call with direct expressions without changing bytes. Inline is independent. Generic budget: 12 fields / 65535 B; equal fixed widths support 64 fields. Fallbacks are explicit. [opt_table=legacy] preserves the old per-frame directory.

Original Rust types remain nested. Only Message gets meta_clock_ticks, meta_kind, id and extra. No duplicate types are emitted. There is no QSL [macro] attribute. Validation, RT and networking


[safety] generates validate, validate_values, deserialize_checked and checked decoding into final storage for owned types. Bounds, metadata, ranges, UTF-8, LZ and exact ending are checked. Malformed built-in data returns QslError before trusted reads. Custom codecs need their own correct validator. The attribute does not add checks to every trusted call.


!config QSL_RT = true;
!config QSL_RT_DEFAULT = 16;


RT defaults off. Only finite schemas receive static slots. Here 16 counts simultaneous occupied buffers per schema, not QPS quantum. Exhaustion returns an error without allocating another buffer. Padding and the 64 MiB per-schema budget are included; deserialize_into remains available.


The native feature supplies Windows NativeRegion, SharedRegion with IPC, and blocking NativeSocket. Shared publication uses release/acquire; processes exchange offsets, not absolute pointers. TCP framing does not replace QSL validation. None of these mechanisms was included in the fresh Criterion run.


Editor, compatibility and proofs


QSL-Extension 0.5: RU/EN, inlays, field hover, outline, completion, definitions and Ctrl+. layout/events/Rust actions. QPS needs no optional tail. Exact analysis follows Rust-template expansion. Advisory estimates are labelled; the native bridge exposes qpsCodecRevision=2. Updating server files requires restarting its process.


Before revision 2, qps selected a different D/index format. Use state_bits to preserve those bytes. quant=Qn retains its numeric operand format and aliases new QPS. Schema, configuration, boundaries and generator revision are part of peer agreement; no len-based format guessing occurs. QBProto handshake/R remains planned.


Lean 4 verifies 18 arithmetic theorems, not all Rust/LLVM/allocation. Checks passed: 69 core unit, 10 serial native, 2 compile-fail and 3 isolated QPS regressions. Four fresh measurements, ASM, harness and hashes are published separately. Intentionally invalid local View demo files were not repaired just to make the demo build pass.
