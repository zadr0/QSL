# Кандидаты оптимизации QSL — без изменений реализации

Дата: 2026-11-04. Это список всех выявленных при данном просмотре кандидатов, а не утверждение, что возможные улучшения исчерпаны. Новые оптимизации движка из списка не внесены. Исправление ролей predict_seq/opt_table и граничного пустого combined-хвоста относятся к отдельной завершённой корректировке поведения.

P1 — сначала проверить узким замером; P2 — зависит от схемы и архитектуры; P3 — анализ/интеграция вне основного горячего пути. Наличие цикла, if или div_ceil само по себе не доказывает потери: требуется машинный код и эксперимент. Предполагаемые ускорения не подменяются числовыми обещаниями.

Свежий отдельный opt_table сохраняет default-кадр. Узкий предварительный контроль показал: N=1 почти одинаков, N=2/3/5/10 — регрессии. Этот профиль не включал новый idle-gate и анализ влияния сборщика метрик, поэтому не используется как строгий межпротокольный итог.

## Общие условия при последующей работе

Одна гипотеза — один узкий контроль; тот же набор данных и wire-контракт. Основные сравнения: default / opt_table / predict_seq / combined, checked / trusted, fresh / reuse. Снимать ASM/LLVM и аппаратные события отдельным диагностическим проходом. Не отключать защиту ради ускорения проверяемого API. Для внешнего ввода сохранять проверку размера, длин, UTF-8, диапазонов, опциональных тегов и восстановленного объёма до небезопасного декодирования. Успехом считается повторяемое улучшение с сохранёнными исходниками и сырыми измерениями.

## После переноса core: StackString reuse

Новый стенд строк показывает отдельную цену reuse для StackString. Этот layout не выбирается prepared_read_layout; стандартный Serializable::deserialize_reuse присваивает результат нового значения. Кандидат — прямая запись в инициализированный StackString без промежуточного возврата. Изменение пока не внесено. Перед выводом о причине нужны проверка ASM и повтор при простое; текущий первый прогон имеет фоновую нагрузку.
