# Одинаковые структуры: QSL / Protobuf / Bincode / Cap’n Proto

Intel Core i5-7400, Windows 11, Rust 1.98.0, target-cpu=native, thin LTO, codegen-units=1. Два противоположных порядка, 1 с прогрева + 3 с измерения, 200 выборок на случай, CI 99%. Среднее двух независимых медиан; исходные CI не объединяются. Фоновая нагрузка записана, система не считается полностью простаивающей.

Выбран фиксированный baseline для каждого протокола. Узкие u16, borrowed-результаты, QSL compact/PS/OT/BM и альтернативные кодировки исключены из этой таблицы. Полная матрица вариантов доступна в [общем отчёте](RESULTS.md). Здесь используются измеренные строки того же полного прохода, без повторного округления или другого набора данных.

| Структура | Общий контракт | Отображение на протоколы |
|---|---|---|
| numeric | четыре u32, значения 0..4095 | QSL u32; Protobuf uint32; Bincode u32 fixint; Cap’n Proto UInt32 |
| optionals | id:u32, a:Option<u8>, b:Option<u16>, c:Option<u32> | Protobuf использует optional uint32 с проверкой диапазонов; Cap’n Proto — явные флаги присутствия и UInt8/16/32. Some(0) сохраняется |
| text | id:u32, String UTF-8, до 1024 байт | Все результаты владеют строкой; Cap’n Proto reader копирует текст в String |

Все кодеки получают одно кольцо из 256 записей; значения и строки побайтно проверяются. Совпадают логические данные и владение, а не бинарные кадры или модель эволюции схем. Для Protobuf типы u8/u16 отсутствуют, поэтому их домен проверяется явно. Подготовка исходных объектов исключена, общий consumer и уничтожение результата включены.
