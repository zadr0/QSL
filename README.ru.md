# QSL — генерация бинарного кодека по схеме

[English](README.en.md) · [Интерактивная документация](docs/index.html) · [Архитектура](docs/architecture.ru.md) · [API](docs/API.ru.md)

QSL специализирует Rust-сериализацию под типы, диапазоны, порядок полей и владение памятью. Сначала обязательные поля, затем опциональные; дополнительные режимы включаются атрибутами.

**QPS сжимает числовые операнды без потерь. opt_table выполняет предиктование по длине. QPS не требует optional-полей.**

```qsl
&Numbers[qps=Q16,safety] { u64(0..15) a; u64(0..15) b; }
&Packet[opt_table,safety] { i32 id; u8? a; u8? b; }
```
`[qps]` выбирает Q16; доступны Q2/Q4/Q8/Q16. `quant=Qn` — совместимый синоним. Прежний D/index-формат выбирается как `state_bits`; смена режима требует согласования сторон. Квант меняет представление точных частного и остатка; экономия возникает из диапазона, а не из потери точности.

Реализованы checked API при `[safety]`, raw/string/byte/CopyGuard/inline-представления, вложенные Rust-структуры-макросы, opt_table с критическими длинами, опциональные статические RT-пулы и Windows-регионы с IPC. QBProto handshake/R остаётся планом. Размер wire-кадра не равен размеру объекта Rust.

## Свежие замеры: только QSL

| Операция | Без QPS, нс | QPS Q16, нс |
|---|---:|---:|
| deserialize_into | 15.57 | 9.56 |
| serialize_into | 7.41 | 13.70 |

Кадр 17–49 B → 3–13 B; QPS дополнительно требует 16 B приватного хвоста для prepared API. В этой схеме чтение быстрее, запись дороже. Прогрев 15 s, измерение 10 s, 200 выборок, CI 99%; лимит 8 GiB. Windows 11 x86-64, i5-7400, RAM 24 GiB 2133 MHz. Это четыре случая одного профиля, без других кодеков и сетевых тестов. [Полные условия, CI, данные и команды](docs/performance.ru.md).

Состояние исходников и проверок: [аудит](SOURCE_AUDIT.md). Этот репозиторий публикует документацию и стенд; он не является Cargo workspace. Измерялся соответствующий локальный dev-qsl, хеши опубликованы. Страница docs/index.html работает без CDN; GitHub Pages можно направить на /docs.
