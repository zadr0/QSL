Quick Schema Language (QSL)은 바이너리 메시지를 기술하는 언어이자, 그 기술을 Rust 코드로 바꾸는 코드 생성기입니다. 필드 타입, 값 범위, 길이 제한을 담아 스키마를 작성합니다. `cargo build` 중에 QSL이 스키마를 읽고, 바이트를 읽고 쓰는 구조체와 메서드를 생성합니다. 프로그램은 런타임에 스키마를 파싱하지 않습니다.

바이너리 직렬화는 값을 바이트로 바꾸고, 역직렬화는 바이트에서 값을 다시 읽습니다. QSL에서는 스키마가 필드를 정의하고 생성된 Rust 코드가 양방향 변환을 수행합니다. 통신 양쪽의 스키마와 속성이 같아야 합니다. [Rust 바이너리 직렬화 빠른 시작](/start/quickstart/)을 읽고 [와이어 형식](/internals/wire-format/)과 [비트 패킹 예제](/guides/smaller-frames/)를 살펴보세요.

```qsl
&Reading[safety,compact] {
    u8(0..7)     kind;
    u8(0..31)    channel;
    u16(0..1023) value;
}
```

이 스키마에서 QSL은 `u8`, `u8`, `u16` 필드를 가진 `Reading` 구조체와, 이를 인코딩·디코딩·검증하는 메서드를 생성합니다. `compact`를 쓰면 세 값이 3 + 5 + 10 = 18비트를 차지하므로 프레임은 4바이트가 아니라 3바이트입니다.

## 직접 정하는 것

- **와이어 레이아웃.** 와이어상의 정수 폭, 그리고 어떤 옵셔널 필드가 있는지 프레임이 표시하는 방식.
- **메모리.** 문자열을 `String`, 빌린 `&str`, 인라인 버퍼 중 무엇으로 만들지, 그리고 디코딩할 때 기존 객체를 재사용할지.
- **검증.** `[safety]`는 검증 디코드 메서드를 생성합니다. 이 메서드는 값을 반환하기 전에 경계, 범위, UTF-8, 전체 크기 한도를 확인합니다.

## 애플리케이션이 맡는 것

QSL은 데이터를 어떻게 표현할지만 정의합니다. 길이 접두사를 붙인 프레임을 TCP로 보내는 얇은 래퍼인 `qsl::RawSocket`을 제외하면 전송은 다루지 않으며, TLS, 라우팅, 스키마 버전 협상 기능도 없습니다. 통신하는 양쪽에는 같은 스키마와 같은 속성이 필요합니다. 포맷을 바꾸면 모든 피어에 한 번에 반영하십시오. QSL은 프레임이 어떤 포맷을 쓰는지 감지하지 않습니다.

생성되는 모든 타입에는 스키마 해시가 상수로 들어 있습니다([스키마 식별](/guides/schema-identity/) 참고). 이 값을 직접 만든 핸드셰이크에서 보낼 수 있습니다. QSL이 대신 해 주지는 않습니다.

## 크레이트
크레이트 | 버전 | 역할
---|---|---
`qsl` | 0.3.0 | 의존성으로 추가하는 크레이트. 런타임을 다시 내보내고 `build_qsl_files`와 속성 매크로를 제공합니다.
`qsl-core` | 0.1.0 | 공용 런타임: 에러, I/O 커서, 문자열 컨테이너, 검증, 버퍼.
`qsl-lexer` | 0.3.0 | `.qsl` 스키마와 `.deq` 설정 파일의 파서, 스키마 빌더.
`qsl-interpreter` | 0.3.0 | 검증된 스키마에서 Rust 소스를 생성합니다.
`qsl-macros-impl` | 0.1.0 | `qsl_macro`, `schem_macro` 속성. `qsl`이 다시 내보냅니다.
대부분의 프로젝트는 `qsl` 하나만 `[dependencies]`와 `[build-dependencies]`에 한 번씩 추가합니다. 크레이트 사이의 의존 관계는 [아키텍처](/internals/architecture/)에 있습니다.

## 현재 상태

QSL 0.3.0은 Windows 11 x86-64와 Rust 1.98에서 개발하고 테스트했습니다. Rust 1.98은 최소 지원 버전이기도 합니다. 속성은 명시적으로 지정할 때만 적용됩니다. 속성은 생성되는 코드를 바꾸지만, 어느 속성도 속도 향상을 보장하지 않습니다. 무엇을 어떤 조건에서 측정했는지는 에 있습니다.
