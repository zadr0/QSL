---
title: 프레임 줄이기
description: 값 범위를 알 때 compact, alignment, qps로 프레임을 줄입니다.
---


기본적으로 정수는 와이어에서 네이티브 폭 전체를 차지합니다. 스키마에 범위가 있으면 QSL은 더 적은 비트로 저장할 수 있습니다. 방법은 두 가지입니다. `compact`는 필드를 비트 단위로 이어 붙이고, `qps`는 범위가 있는 각 숫자를 고정된 퀀텀에서 나누고 그 부분들을 패킹합니다.

## compact

`compact`는 범위가 있는 각 값을 `x - min`으로 바꿔 `bit_length(max - min)`비트에 저장합니다. 필드는 최하위 비트부터 차례로 채워지며 바이트 경계를 넘을 수 있습니다.

```qsl
&Sample[safety,compact] {
    u8(0..7)     kind;      // 3비트
    u8(0..31)    channel;   // 5비트
    u16(0..1023) value;     // 10비트
}
```

합계 18비트이므로 4바이트가 아니라 3바이트입니다. `kind = 5`, `channel = 17`, `value = 513`일 때 프레임은 `8d 01 02`입니다. `compact`가 없으면 `05 11 01 02`입니다. 아래에서 값과 인코딩을 바꿔 보십시오.


허용 값이 하나뿐인 필드(`u8(5..5)`)는 0비트를 차지합니다. Rust 타입은 바뀌지 않습니다. `value`는 메모리에서 여전히 `u16`입니다.

`compact`는 `predict_seq`와 함께 쓸 수 없습니다. `[safety]`가 있으면 디코더는 풀어낸 모든 값이 범위 안에 있는지, 쓰지 않는 비트가 0인지 검사합니다.

## alignment

`compact`와 함께 쓰면 `alignment`는 각 필드를 바이트 경계에서 시작합니다. 프레임이 커지는 대신 읽기가 단순해집니다. 위 예제에서는 프레임이 다시 `05 11 01 02`, 4바이트가 됩니다. `compact` 없이 쓰면 `alignment`는 포맷에 영향을 주지 않습니다.

이것은 프레임 안에서 필드를 정렬하는 것이지, 버퍼의 메모리 정렬이 아닙니다.

## qps

`qps`(별칭 `quant`)는 정적 경계가 있는 숫자 필드를 위한 가역 패킹입니다. 각 값은 순위(rank) `r = x - min`으로 저장됩니다. 이 순위를 퀀텀 `Q`에 따라 두 부분으로 나누고, 정적 시프트와 마스크로 다시 합칩니다. 정보 손실은 없습니다. 퀀텀은 포맷의 일부입니다.

```qsl
&Packed[qps,safety] {
    u64(0..15) f0;
    u64(0..15) f1;
    // ... f7까지
}
```
속성 | 의미
---|---
`qps` | `qps=Q16`과 같습니다.
`qps=Q2`, `Q4`, `Q8`, `Q16` | 퀀텀. 바이트는 바뀔 수 있지만 프레임 길이는 바뀌지 않습니다.
`quant=Qn` | `qps=Qn`과 같습니다. 값 없이 `quant`만 쓰면 에러이고, 두 이름을 함께 써도 에러입니다.
`qps`는 숫자만 패킹합니다. 문자열, 배열, 그 길이는 각자의 코덱을 유지하며, 숫자 필드가 그보다 앞에 와야 합니다. 어떤 옵셔널 필드가 있는지는 예측하지 않습니다. 패킹으로 얻는 것이 없으면 타입은 일반 인코딩을 씁니다.

`qps`가 있는 타입에는 `compact`, `alignment`, `optionals=bitmap`, `opt_table=legacy`를 함께 지정할 수 없습니다. 빌드가 실패합니다.

## 예제 실행 결과

```text
8 ranged u64 values: raw=64 B, compact=4 B, QPS=4 B; restored f0=3, f7=10
Scalar Q16: 64 useful B -> 4 wire B
Mixed Q16: 16 scalar B -> 1 B; string length stays 4 B, string stays 1024 B; frame=1029 B
```

`0..15` 범위의 값 8개는 각각 4비트, 합계 32비트가 필요합니다. 혼합 메시지에서는 숫자 두 개가 1바이트로 패킹되고, 1024바이트 문자열은 4바이트 길이를 그대로 유지합니다.

:::note[ByteQps는 별개의 API입니다]
`qsl::qps::ByteQps<Q>`는 임의의 바이트를 16바이트 `QPB3` 헤더 뒤에 압축해 넣습니다. 스키마 속성 `qps`가 아니라 런타임 API이며, 두 포맷은 서로 호환되지 않습니다. 작은 프레임에는 도움이 되지 않습니다. 헤더만으로 16바이트가 듭니다.
:::
