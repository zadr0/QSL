:::note[Локальная редакция]
Рабочее дерево dev-qsl на 14 ноября 2026 года. Новые API не равнозначны опубликованному crate qsl 0.3.0.

Исходная задача QSL — обмен заранее описанными данными между сторонами, которые контролируют схему, ограничения значений и способ работы с памятью. Анализ выполняется при сборке; результат — конкретные Rust-типы и специализированные бинарные методы. Проект развивается как самостоятельное индивидуальное решение на основе практики и логической модели.

Область применения: внутренние протоколы, телеметрия, повторяющиеся записи и приложения с известными границами данных. Цена специализации — необходимость точно задать диапазоны, длины, владение, присутствие полей и совместимость сторон.

Базовые инварианты:

1. Дополнительные механизмы и атрибуты опциональны; обязательный порядок полей — required → optional.
2. Восстановление сохраняет точность в пределах объявленного домена.
3. Отсутствующий optional не заменяется initializer/default и не имеет payload.
4. Ни один оптимизированный load не получает разрешение читать недоступный байт или неинициализированный слот.
5. Схема и wire-значимые опции определяют формат. Физический layout Self — отдельное понятие.
6. Checked API проверяет данные; unsafe API сохраняется с явными обязанностями вызывающего кода.

QSL не выполняет автоматическое согласование версий, маршрутизацию, шифрование, аутентификацию или повторную доставку. Это ответственность приложения/транспорта. QBProto и автоматическое рукопожатие набора схем пока не реализованы.
