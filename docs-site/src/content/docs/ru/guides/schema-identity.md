Идентичности вычисляются при анализе, Rust хранит константы; hot path не хэширует и не добавляет digest в кадр автоматически.
Идентичность | Содержимое
---|---
Strict | Имена схемы/полей и каноническое описание формата/ограничений
Light | То же описание без имён схемы/полей
Учитываются типы, домены, wire-порядок, optional/теги, кодеки, значимый padding/alignment, quantum и версия. Safety, inline, initializer, RT и физические изменения без изменения wire исключаются. Ownership не меняет идентичность, если кодек действительно совпадает.

Сравнивать нужно algorithm, version, digest и complete. xxHash означает XXH3-64, xxHash128 — XXH3-128; оба некриптографические и не гарантируют абсолютного отсутствия коллизий. Opaque custom даёт complete=false: скрытую реализацию нужно согласовывать отдельно.

Light не подтверждает семантику переименованных полей. Смена диапазона/порядка/кодека требует проверки совместимости, даже если несколько значений дали одинаковые байты. Byte-copy barrier и numeric array packing могут различаться в COMPACT, что отражается в hash. Для проверенных эквивалентных step=1 scalar-схем сохранены прежние wire/light hash.
