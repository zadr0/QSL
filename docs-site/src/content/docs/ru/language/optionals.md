---
title: "PS, OT и bitmap"
description: "Документация QSL: PS, OT и bitmap."
---


```qsl
&P[safety] {
    i32 id;
    u8? a;
    u8? b;
}
```

В обычном формате required-значения не получают отдельный тег. Optional-метаданные определяются кодеком: один presence-бит, count/tags либо BM. Отсутствующее поле не записывает значение/default.
Механизм | Функция
---|---
Default | Базовое кодирование присутствия
predict_seq / PS | Длина payload → числовой индекс/состояние → присутствие
opt_table / OT | Тег → статическая функция-читатель
PS+OT | Согласованный граф длин и tag dispatch
optionals=bitmap / BM | Маска только optional-полей в wire
PS не может сам различить произвольные наборы одной длины. Пропуск тегов зависит от доказанной однозначности схемы и формата; неоднозначность не снимается предположением. OT не заменяет индекс длины. QPS не предсказывает optional.

BM v2 выбирает u8/u16/u32/u64/u128 по числу optional. Payload следует порядку обхода set-битов текущего BM-кодека, который может отличаться от default. Ревизия BM должна совпадать у обеих сторон.

`aggressive[bitmap]` относится к **Self**: private MaybeUninit&lt;T&gt;, native-маска с bit=tag−1 и методы get_name/set_name/clear_name. Отсутствующий слот не читается; Drop затрагивает только активные слоты. Этот механизм независим от wire BM.

Обычные numeric optional могут иметь отдельное значение/маску либо доказанную Option<NonZero*>-нишу. Поэтому try_new и методы доступа предпочтительнее предположения, что каждое поле физически Option&lt;T&gt;. Для DomainInteger ранговые ниши учитывают step/set и полные границы; полный u128 без свободного состояния сохраняет отдельную маску присутствия.

opt_table=legacy и state_bits — явные старые режимы совместимости. Их нельзя без согласования приравнивать к новым PS/OT/QPS.
