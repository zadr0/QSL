ソケット、ファイル、別のプロセスから届くバイト列は信頼できません。これらはチェック付きメソッドでデコードしてください。チェック付きメソッドは、`safety` 属性を持つ型にだけ生成されます。

```qsl
&Packet[safety] {
    u32 id;
    str(1..100) text;
}
```

```rust
let bytes = packet.serialize_checked()?;
let decoded = Packet::deserialize_checked(&bytes)?;

// 既存のメモリにデコードすることもできる：
let mut slot = std::mem::MaybeUninit::uninit();
let decoded: &mut Packet = Packet::deserialize_checked_into(&bytes, &mut slot)?;
```

## チェック付きデコードが検証する内容

生成されたデコーダは、値を返す前に次の点をチェックします。

- フレームの長さが最小の有効フレーム以上であり、すべてのフィールドを含み、スキーマどおりの位置で終わっていること。
- すべての数値が、宣言された範囲内にあること。
- すべての文字列と配列の長さが、上下限の範囲内にあること。
- 文字列が有効な UTF-8 であること。
- オプションフィールドのメタデータが、スキーマと矛盾しないこと。
- パディングのビットとバイトがゼロであること。
- 圧縮文字列を復元したサイズが、上限を超えないこと。
- デコードした値の合計サイズが、`MAX_DATA_SIZE` 以内に収まること。

検証とデコードは 1 回のパスで行われます。事前に `validate` を呼ぶ必要はありません。デコードに失敗した場合、`deserialize_checked_into` は `slot` を未初期化のままにします。

## サイズの上限

`MAX_DATA_SIZE`（デフォルトは 65535 バイト）は、入力フレームとデコード後のペイロードの合計を制限します。フレームから読み取った長さは、メモリを確保する前に、上下限とこのサイズ上限に照らしてチェックされます。この値は [DEQ ファイル](/language/deq/)で上げ下げできます。

リポジトリの safety サンプルは、次の型に対して 3 つの不正なフレームを `validate` に渡します。

```qsl
&Bounded[safety] { u8(1..3) kind; str(1..100) name; }
```
入力 | 結果
---|---
`09 01 00 00 00 61` | `InvalidValue`：`kind` が 9 で、`1..3` の範囲外です。
`01 ff ff ff ff` | `UnexpectedEof`：5 バイトは、最小の有効フレームである 6 バイトより短いためです。
`01 01 00 00 00 ff` | `InvalidUtf8`：`ff` は UTF-8 ではありません。
`01 ff ff ff ff 61` のように、フレームのサイズは有効でも長さが偽装されている場合は、`InvalidValue` で失敗します。バイトをコピーする前に、長さが上限の `100` と比較されるからです。

## チェック付きエンコード

`serialize_checked` は、値をスキーマ（範囲、長さ、固定長文字列の UTF-8、`MAX_DATA_SIZE`）と照合し、新しい `Vec<u8>` を返します。`serialize_checked_to` は、渡されたスライスに書き込み、書き込んだバイト数か `BufferTooSmall` を返します。最後のサイズチェックで失敗した場合、スライスの一部がすでに書き込まれていることがあります。どちらのメソッドも、`[safety]` の有無にかかわらずすべての型に生成されます。

## チェックなしのメソッド

`[safety]` はチェック付きメソッドを追加しますが、チェックなしのメソッドを取り除くわけではありません。`deserialize_into` などの `qsl::Serializable` トレイトのメソッドや、生ポインタを扱うリーダーは、次のことを前提とします。

- フレームが完全で、このスキーマに対して有効であること。
- 書き込み先のメモリが十分に大きく、正しくアラインされていて、入力と重なっていないこと。
- 借用した入力が、結果より長く生存すること。

これらのメソッドは、自分で生成したフレームか、検証済みのフレームにだけ使ってください。これらは `unsafe` です。0.3.0 以降は `Serializable::serialize` と `BorrowSerializable::serialize` も `unsafe` です。RT プールを持つ型、または `qps` パッキングが有効な型に生成される `serialize()` は別のメソッドで、安全に呼び出せ、`Result` を返します。

## 検証の限界

- 検証で証明できるのは、バイト列がスキーマに対して有効な形をしていることです。どのスキーマがそのバイト列を生成したかは証明できません。同じレイアウトを持つ 2 つのスキーマは、同じバイト列を受け入れます。ハンドシェイクでは[スキーマハッシュ](/guides/schema-identity/)か独自の識別子を使ってください。
- 送信者の認証は行いません。
- [カスタム型](/guides/custom-types/)の安全性は、その `qsl_validate` の実装で決まります。デフォルトの実装はすべての入力を拒否します。

生成器は証明されたフレームの最大サイズから出力型を選びます。STACK_LIMIT 以下なら等号を含め `StackOut<N>`、より大きい場合や上限が不明な場合は alloc::`Vec<u8>` を使います。送信ヘッダーは含み、出力オブジェクト自体の長さや整列メタデータは含みません。
