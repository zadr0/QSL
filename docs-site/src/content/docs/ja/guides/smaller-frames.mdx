---
title: フレームを小さくする
description: 値の範囲がわかっている場合に、compact、alignment、qps でフレームを小さくします。
---


デフォルトでは、整数はワイヤ上でネイティブ幅をすべて使います。スキーマで範囲を指定すると、QSL はより少ないビット数で値を格納できます。仕組みは 2 つあります。`compact` はフィールドをビット単位で詰め、`qps` は範囲付きの各数値を固定のクォンタムで分割し、分割した部分を詰めます。

## compact

`compact` は、範囲付きの各値を `x - min` として `bit_length(max - min)` ビットで格納します。フィールドは最下位ビットから順に隙間なく詰められ、バイト境界をまたぐこともあります。

```qsl
&Sample[safety,compact] {
    u8(0..7)     kind;      // 3 ビット
    u8(0..31)    channel;   // 5 ビット
    u16(0..1023) value;     // 10 ビット
}
```

合計 18 ビットなので、4 バイトではなく 3 バイトになります。`kind = 5`、`channel = 17`、`value = 513` の場合、フレームは `8d 01 02` です。`compact` なしでは `05 11 01 02` です。下で値とエンコーディングを変えてみてください。


許される値が 1 つだけのフィールド（`u8(5..5)`）は 0 ビットです。Rust の型は変わりません。`value` はメモリ上では `u16` のままです。

`compact` は `predict_seq` と組み合わせられません。`[safety]` を指定すると、デコーダは展開したすべての値が範囲内にあることと、未使用のビットがゼロであることをチェックします。

## alignment

`compact` と一緒に指定すると、`alignment` は各フィールドをバイト境界から開始させます。フレームは大きくなりますが、読み取りは単純になります。上の例では、フレームは再び `05 11 01 02` の 4 バイトになります。`compact` がない場合、`alignment` はフォーマットに影響しません。

これはフレーム内でのフィールドのアラインメントであり、バッファのメモリアラインメントではありません。

## qps

`qps`（別名 `quant`）は、静的な上下限を持つ数値フィールドを可逆的にパックします。各値はランク `r = x - min` として格納され、クォンタム `Q` によって 2 つの部分に分割され、静的なシフトとマスクで再結合されます。情報は失われません。クォンタムはフォーマットの一部です。

```qsl
&Packed[qps,safety] {
    u64(0..15) f0;
    u64(0..15) f1;
    // ... f7 まで同様
}
```
属性 | 意味
---|---
`qps` | `qps=Q16` と同じです。
`qps=Q2`、`Q4`、`Q8`、`Q16` | クォンタム。バイト列は変わることがありますが、フレーム長は変わりません。
`quant=Qn` | `qps=Qn` と同じです。値なしの `quant` はエラーで、両方の名前を使うこともエラーです。
`qps` がパックするのは数値だけです。文字列、配列、その長さはそれぞれのコーデックのままで、数値フィールドはそれらより前に置く必要があります。どのオプションフィールドが存在するかは予測しません。パックしても効果がない場合、その型は通常のエンコーディングを使います。

`qps` を持つ型には、`compact`、`alignment`、`optionals=bitmap`、`opt_table=legacy` を指定できません。指定するとビルドが失敗します。

## サンプルでの結果

```text
8 ranged u64 values: raw=64 B, compact=4 B, QPS=4 B; restored f0=3, f7=10
Scalar Q16: 64 useful B -> 4 wire B
Mixed Q16: 16 scalar B -> 1 B; string length stays 4 B, string stays 1024 B; frame=1029 B
```

`0..15` の範囲の値 8 つは、それぞれ 4 ビット、合計 32 ビットを必要とします。mixed のメッセージでは 2 つの数値が 1 バイトに詰められ、1024 バイトの文字列は 4 バイトの長さを保ちます。

:::note[ByteQps は別の API です]
`qsl::qps::ByteQps<Q>` は、任意のバイト列を圧縮し、16 バイトの `QPB3` ヘッダの後ろに格納します。これはランタイム API であり、スキーマ属性の `qps` とは別物です。2 つのフォーマットに互換性はありません。小さなフレームには役立ちません。ヘッダだけで 16 バイトを使います。
:::
