Quick Schema Language (QSL) は、バイナリメッセージを記述する言語と、その記述を Rust コードに変換するコードジェネレータです。フィールドの型、値の範囲、長さの上限を書いたスキーマを用意すると、`cargo build` の間に QSL がスキーマを読み、バイト列を読み書きする構造体とメソッドを出力します。プログラムが実行時にスキーマを解析することはありません。

バイナリシリアライズは値をバイト列に変換し、デシリアライズはバイト列から値を読み戻します。QSL ではスキーマがフィールドを定義し、生成された Rust コードが両方向の変換を行います。通信する双方でスキーマと属性を一致させる必要があります。[Rust のバイナリシリアライズのクイックスタート](/start/quickstart/)から始め、[ワイヤフォーマット](/internals/wire-format/)と[ビットパッキングの例](/guides/smaller-frames/)を参照してください。

```qsl
&Reading[safety,compact] {
    u8(0..7)     kind;
    u8(0..31)    channel;
    u16(0..1023) value;
}
```

このスキーマから、QSL は `u8`、`u8`、`u16` のフィールドを持つ `Reading` 構造体と、それをエンコード、デコード、検証するメソッドを生成します。`compact` を指定すると 3 つの値は 3 + 5 + 10 = 18 ビットになり、フレームは 4 バイトではなく 3 バイトになります。

## 制御できること

- **ワイヤレイアウト。** ワイヤ上の整数幅と、どのオプションフィールドが存在するかをフレームで示す方法。
- **メモリ。** 文字列を `String`、借用した `&str`、インラインバッファのどれにするか。デコード時に既存のオブジェクトを再利用するかどうか。
- **検証。** `[safety]` はチェック付きのデコードメソッドを生成します。このメソッドは値を返す前に、上下限、範囲、UTF-8、合計サイズの上限を検証します。

## アプリケーション側に残ること

QSL が定義するのはデータの表現方法です。TCP 上で長さプレフィックス付きのフレームを送る薄いラッパー `qsl::RawSocket` を除き、トランスポートは扱いません。TLS、ルーティング、スキーマのバージョンネゴシエーションの機能もありません。通信の両側に同じスキーマと同じ属性が必要です。フォーマットを変更する場合は、すべてのピアに同時に展開してください。フレームがどのフォーマットで書かれたかを、QSL は検出しません。

生成されるすべての型は、スキーマハッシュを定数として持っています（[スキーマの識別](/guides/schema-identity/)を参照）。このハッシュを独自のハンドシェイクで送ることはできますが、その処理を QSL が行うわけではありません。

## クレート
クレート | バージョン | 役割
---|---|---
`qsl` | 0.3.0 | 依存関係に追加するクレート。ランタイムを再エクスポートし、`build_qsl_files` と属性マクロを提供します。
`qsl-core` | 0.1.0 | 共有ランタイム。エラー、I/O カーソル、文字列コンテナ、検証、バッファ。
`qsl-lexer` | 0.3.0 | `.qsl` スキーマと `.deq` 設定ファイルのパーサ、スキーマビルダー。
`qsl-interpreter` | 0.3.0 | 検証済みのスキーマから Rust のソースコードを生成します。
`qsl-macros-impl` | 0.1.0 | `qsl_macro` 属性と `schem_macro` 属性。`qsl` から再エクスポートされます。
ほとんどのプロジェクトでは `qsl` を追加するだけで済みます。`[dependencies]` と `[build-dependencies]` に 1 回ずつ追加します。クレート間の依存関係は[アーキテクチャ](/internals/architecture/)にまとめています。

## 開発状況

QSL 0.3.0 は Windows 11 x86-64 と Rust 1.98 で開発、テストされています。Rust 1.98 はサポートする最小バージョンでもあります。属性はすべてオプトインです。属性は生成コードを変えますが、どの属性も高速化を保証するものではありません。何をどの条件で計測したかはにあります。
