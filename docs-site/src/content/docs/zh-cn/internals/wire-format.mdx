QSL 帧中只有值以及 schema 要求的元数据。帧中没有类型信息、字段名，也没有 schema 哈希。

## 帧的布局

```text
[optional-field metadata] [required values in declaration order] [present optional values]
```

`opt_table=legacy` 是这一顺序的唯一例外：它的偏移表位于必填字段的值之后。类型没有可选字段时，元数据部分为空。

## 值
值 | 默认编码 | 使用 `compact` 时
---|---|---
整数 | 小端序，原生宽度 | `x - min`，占 `bit_length(max - min)` 位
`str`、`str(A..B)` | `u32` 字节长度，后跟 UTF-8 | 长度存为相对下界的偏移量，占范围允许的最少位数，然后从下一个字节边界开始写 UTF-8
带 `decompress=true` 或 `decompress=true` 的 `str(A..B)` | 1、2 或 4 字节的头部，分别对应上界不超过 127、不超过 32767 和更大的情况；头部最高位标记是否压缩 | 相同
`str(N)` | `N` 字节，没有长度 | 相同
`array<T>`、`array<T>(A..B)` | `u32` 元素个数，后跟各元素 | 元素个数存为相对下界的偏移量，后跟各元素
`array<T>(N)` | `N` 个元素，没有元素个数 | 相同
`padding(N)` | `N` 个零字节 | 相同
使用 `compact` 时，字段从最低有效位开始逐位打包，可以跨越字节和机器字。生成器会选择寄存器宽度，并为每个字段生成固定的移位和掩码序列。


上面的字节由浏览器按照与 Rust 生成器相同的规则计算。当 `kind = 5`、`channel = 17`、`value = 513` 时：
编码方式 | 字节
---|---
默认 | `05 11 01 02`
`compact` | `8d 01 02`
`compact` + `alignment` | `05 11 01 02`
## 可选字段元数据

**默认**：只有一个可选字段时，用一个存在位。有多个时，先用 `bit_length(optional_count)` 位存储存在字段的个数，然后为每个存在的字段用 `bit_length(max_tag - 1)` 位存储其标签减 1。头部从最低有效位开始打包，并填充到整字节（使用 `compact` 时除外）。头部长度取决于存在的字段数。见[完整示例](/language/optionals/)。

**位图**：只覆盖可选字段的小端序掩码，长度为 0、1、2、4、8 或 16 字节。标记 1 对应最高有效位。值按标记从大到小的顺序排列。


**predict_seq**：存在信息由载荷长度推导，因此没有元数据。使用 `predict_seq,opt_table` 时，帧以固定头部开始：如果仅凭长度有歧义，每个可选字段占一个存在位；除最后一个以外，每个变长可选字段还有 1、2 或 4 字节的长度。

**opt_table=legacy**：位于必填字段的值之后，先是一个计数字节，然后每个可选字段一个小端序 `u32`：字段不存在时为 `0`，否则为该值在可选载荷中的偏移加 1。

## 使用 decompress=true 的字符串

带范围的压缩字符串使用上面所说的内联头部，载荷经过压缩时最高位置 1。QSL 只对 32 字节及以上的字符串尝试压缩；压缩不能让结果变小时，写入原始字节。

对于带 `decompress=true` 且 `N` 不小于 32 的固定长度 `str(N)`，编码要么是 `N` 个原始字节，要么是一个 `ff` 标记字节、1 或 2 字节的长度，再加上压缩后的载荷。有效的 UTF-8 不会以 `ff` 开头，因此两种情况不会混淆。

## 兼容性

修改以下任意一项都会改变格式：字段顺序、类型、范围、哪些字段是可选的、`compact`、与 `compact` 同用的 `alignment`、可选字段模式、`qps` 及其 quantum、`decompress`、`decompress=true`。帧内没有版本信息。[Schema 哈希](/guides/schema-identity/)会随格式变化，可以在带外交换。
