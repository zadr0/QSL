# Runtime no_std: память, генерация и проверка

Локальная реализация dev-qsl, 14 ноября 2026 года. Изменения ещё не опубликованы. Сайт не обновлялся в этом проходе; новые замеры отложены.

## Границы крейтов

| Крейт | Ответственность |
|---|---|
| qsl-core | Всегда no_std: byte/bit I/O, сериализация, контейнеры, примитивы, валидация, UTF-8/LZ, QPS, dyn и трейты памяти |
| qsl-rt | Всегда no_std: конкретные локальные и межпоточные пулы; зависит от контрактов core |
| qsl-lexer | Компьютер сборки: QSL/DEQ, схемы, Rust-метаданные, анализ и CompilationPlan |
| qsl-interpreter | Компьютер сборки: генерация специализированного Rust с путями core/alloc |
| qsl | Фасад runtime; компилятор подключается отдельной feature compiler |

Runtime не копируется в lexer/interpreter. ByteTransport/RawSocket задают независимый от ОС контракт транспорта и u32 LE framing; реализацию сокета предоставляет приложение. Платформенных Windows/IPC-модулей здесь нет.

## no_std и alloc

no_std исключает стандартную библиотеку Rust, но допускает alloc. Возможность alloc включена по умолчанию в core: доступны alloc::String, alloc::Vec, SerOut, Box<InlineString> и владеющие QPS-буферы. QSL не объявляет global_allocator; конечное приложение предоставляет аллокатор. Стандартные alloc::String/Vec пока используют его, а не собственный локальный аллокатор QSL.

Для runtime без heap: qsl с default-features=false. Для runtime с alloc: дополнительно features=["alloc"]. Генератор подключается через build-dependencies; std и аллокации build.rs относятся к компьютеру сборки и не входят в целевой runtime.

Трейты FrameStorage/FramePool позволяют приложению задать выходную память. Они не меняют аллокатор внутри стандартных String/Vec. Возможность будущего локального аллокатора отделена от нынешнего контракта контейнеров.

## Строки и массивы

- StackString<N,L> хранит raw UTF-8 внутри объекта; InlineArray<T,N,L> — ограниченный массив. Инициализирован только активный префикс; для массива освобождаются только созданные элементы.
- Обычный InlineString<N,L> соответствует QSL-LZ. Большой контейнер генерируется как Box<InlineString<N>> и восстанавливается прямо в heap без промежуточного N-байтового объекта на стэке. На wire кодек не меняется от выбора места хранения.
- Обычные владеющие строки/массивы используют alloc::String/Vec; lifetime-режим может генерировать &str. Длины UTF-8 измеряются в байтах: «Яa» занимает 3 байта.
- Фиксированные строки/массивы используют [u8;N]/[T;N], когда позволяют раскладка и строгий лимит; большие фиксированные строки могут храниться как String.
- Явное aggressive[shift=true] выбирает len+1 в подходящем NonZeroU8/U16/U32 для допустимых inline-строк и массивов. None и Some(empty) различаются. Wire от физического слова длины не меняется; автоматическое включение shift не принято предыдущими замерами.

Источник Rust и типизированный Builder теперь одинаково трактуют обычный InlineString как QSL-LZ. Это меняет wire и hash старых схем, импортированных из Rust с прежней raw-трактовкой InlineString. Отдельное существующее правило native-шаблона aggressive_transmutate преобразует поле в фиксированный [u8;N]; это уже другой итоговый тип и ABI-контракт.

## Строгие лимиты

STACK_LIMIT по умолчанию равен 256 B и учитывает слово длины и выравнивание inline-контейнера. StackString<252,u32> занимает 256 B, а ёмкость 253 требует 260 B. Для InlineArray<u64,32,u32> требуется 264 B. Одного умножения числа элементов на размер элемента недостаточно.

Это лимит встроенного контейнера: оболочка Option, остальные поля, стек вызывающей функции и рекурсивные кадры считаются отдельно. loyal_cache дополнительно требует допустимую раскладку всей схемы и не разрешает незаметно заменить недопустимый inline-контейнер на heap.

MAX_DATA_SIZE по умолчанию равен 65535 и ограничивает входной/восстановленный кадр и суммарный объём декодирования. Для Box<InlineString<512,u32>> checked-путь до выделения списывает весь native-объект размером 516 B, даже если текст занимает 1 B. Два таких поля требуют 1032 B; raw и LZ следуют одинаковому правилу. Метаданные аллокатора и RSS этот бюджет точно не измеряет.

Каждый LZ-токен отдельно проверяется до записи: длина вывода, доступный литерал, допустимое расстояние назад и итоговая вместимость. Затем проверяется UTF-8. Поддельный заголовок не разрешает переполнить восстановленный буфер. Некорректный первый токен отклоняется до выделения Box; последующие токены разбираются ровно один раз перед раскрытием. При ошибке значение не публикуется.

## new и reuse

Сгенерированный deserialize_into принимает разные назначения через DeserializeDestination. &mut Self означает уже созданный объект и путь reuse; указатель/MaybeUninit имеют отдельный контракт создания. Нельзя передавать неинициализированную память как &mut Self.

Для схем без optional, lifetime, dyn и scalar QPS подготовленный unsafe reuse сохраняет буферы required String, Box<InlineString> и примитивных Vec; inline-контейнеры обновляются на месте. Проверены пустые/непустые переходы, UTF-8, raw/LZ, фиксированные строки, полные u128/i16, COMPACT-барьеры байтовых массивов и NonZero-длины. Указатели выделенных буферов остаются прежними.

Вызывающий код обязан предоставить корректный полный кадр нужной схемы, отсутствие перекрытия входа с назначением и достаточную ёмкость всех сохраняемых буферов. Unsafe-путь не проверяет и не увеличивает её. REUSES_STORAGE не обещает отсутствие аллокаций у произвольного custom-кодека. Optional/dyn/QPS и checked-создание имеют отдельные пути; общего обещания reuse для них нет.

## Поставщики qsl-rt

LocalRegions<CAP,N> использует Cell-маску без атомиков и может жить внутри функции. Он не Sync, его lease не Send. StaticRegions<CAP,N> использует атомарную маску и допускает межпоточное использование. Оба предоставляют 1–64 эксклюзивных слота; Drop освобождает слот, try_acquire сразу возвращает PoolExhausted при заполнении. Сгенерированный RT serialize тоже возвращает ошибку, а не ждёт слот.

FrameStorage публикует только инициализированный префикс. PreparedFramePool::ZEROED/new_zeroed дополнительно инициализируют всю ёмкость для padded-ядер. new() такой гарантии не даёт. QuantizedRegions принимает заимствованный локальный пул, статическое время жизни не обязательно. Это пулы процесса, не IPC.

## Доказательство сборкой

Исполняемый пример qsl-core/tests/no-alloc использует no_std/no_main и настоящие сгенерированные схемы: raw/compact числа, UTF-8, StackString/InlineString, NonZero-массивы, typed-макросы, borrowed text, bitmap/теги, native-регионы, QPS и RT. Он завершается с кодом 0. В реальной команде линковки нет Rust std/alloc rlib. Системный выход и C memory primitives принадлежат только тестовому приложению Windows.

Отдельная библиотека qsl-core/tests/alloc тоже no_std и проверяет String/Vec/Box, malformed LZ, согласованность checked-бюджетов и reuse. Её тестовый harness использует std и аллокатор; это не зависимость целевой библиотеки. Оба режима ядра и qsl-rt проверены для wasm32-wasip2.

Lean4 доказывает арифметические границы восстановления и бюджетов. Он не доказывает Rust ownership/provenance, UTF-8, отсутствие UB или производительность. Miri/санитайзеры и аппаратные счётчики требуют отдельной среды.

## Воспроизведение

Команды выполняются из dev-qsl; no-allocator executable предназначен для Windows.

~~~text
cargo test --manifest-path qsl-core/Cargo.toml --all-features --locked
cargo test --manifest-path qsl-core/Cargo.toml --no-default-features --locked
cargo test --manifest-path qsl-rt/Cargo.toml --locked
cargo run --manifest-path qsl-core/tests/no-alloc/Cargo.toml --locked
cargo test --manifest-path qsl-core/tests/alloc/Cargo.toml --locked
cargo check --manifest-path qsl-core/Cargo.toml --target wasm32-wasip2 --no-default-features --locked
cargo check --manifest-path qsl-core/Cargo.toml --target wasm32-wasip2 --all-features --locked
cargo check --manifest-path qsl-rt/Cargo.toml --target wasm32-wasip2 --locked
~~~

## Выход serialize: выбор при генерации

Для обычных схем serialize() и serialize_checked() возвращают Result с конкретным выходным типом. Если доказанный максимум кадра не превышает STACK_LIMIT, включая равенство, выбран StackOut<N>; больший или неизвестный максимум выбирает alloc::Vec<u8>. Слово длины и выравнивание самого StackOut в этот порог не входят. Выбор закреплён в сгенерированном Rust и не создаёт ветвления stack/heap во время записи.

StackOut<N> содержит неинициализированную ёмкость и u32 фактической длины; доступны as_slice(), AsRef<[u8]>, Deref, len(), is_empty(), capacity(). Читается только записанный префикс. Например, кадр с максимумом 64 B получает StackOut<64>. При STACK_LIMIT=256 кадр до 256 B включительно использует StackOut, а кадр 257 B — Vec. Размер кадра включает передаваемые заголовки; служебные данные объекта буфера не учитываются. Для двух строк по 4 KiB выбирается Vec даже при коротких фактических значениях; резервируется фактически необходимая ёмкость, а не весь максимум схемы.

Сжатие не используется как обещание уменьшенного максимума: учитывается raw fallback и заголовки. Небольшой QPS serialize() сохраняет типизированный QuantizedLease с StackOut и метод frame(); явно включённый QSL_RT сохраняет пул и lease. serialize_checked_to и serialize_to продолжают писать в память вызывающего кода. Unsafe Serializable/BorrowSerializable::serialize возвращает SerializeOutput::Output, без проверки значений; ручному типу нужен явный SerializeOutput. Непроверяемый путь не заменён checked-обёрткой.

Интерпретатор использует qsl_lexer::layout и qsl_core напрямую. Файлы, содержавшие только переэкспорты runtime или layout, удалены; публичные экспорты фасада сосредоточены в lib.rs. Основные пути реализации: qsl_core::storage, qsl_core::serialize, qsl_core::payload_quant, qsl_lexer::layout и qsl_lexer::payload_quant.

### Настройка лимита выхода

В DEQ: `!config STACK_LIMIT = 128;`. В Builder: `config(|c| { c.stack_limit(128); })`. Оба пути задают один GenerationConfig.stack_limit; отдельного порога serialize нет. Ёмкость StackOut определяется доказанным максимумом кадра; STACK_LIMIT ограничивает число wire-байтов включительно. Изменение лимита не меняет wire-байты и хэши схемы.

Граничная проверка при STACK_LIMIT=64: кадр 64 B использует StackOut<64>, кадр 65 B — Vec. При значении 0 в стек допускается кадр с доказанным максимумом 0 B. Проверены также лимиты 63, 65, 128 и 256. Компактные числовые домены учитываются по ширине ранга: шестнадцать u128 с диапазоном 0..15 дают максимум кадра 8 B, а не 256 B.

В no_std без alloc большие заимствованные схемы сохраняют serialize_checked_to/serialize_to с переданной памятью. Отсутствие heap-выхода не отключает эти методы. Это проверено исполняемым примером без аллокатора.
