# QSL

QSL is a data-description language and a generator of specialized Rust binary codecs.
Peers agree on field order, value ranges, lengths and codecs. QSL analyzes the schema
during the Cargo build and emits concrete Rust structures and methods for exchanging bytes.

It targets controlled internal protocols, IPC, telemetry and repeated records with known
layouts. Developers specify memory bounds, ownership and input validation. Applications
provide version negotiation, routing and TLS.

## Quick start

Requires Rust 1.98 or later. Release checks run on Windows 11 x86-64.

Create an application with cargo new qsl-demo, then add the four files below.
Keep the package section generated by Cargo. Use the same QSL version in application
and build dependencies.

### 1. Cargo.toml

```toml
[dependencies]
qsl = "=0.2.0"

[build-dependencies]
qsl = "=0.2.0"
```

### 2. user.qsl

```qsl
&User[safety] {
    u64 id;
    str(1..100) name;
}
```

### 3. build.rs

```rust,ignore
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let out = std::path::PathBuf::from(std::env::var_os("OUT_DIR").unwrap());
    qsl::build_qsl_files(&["user.qsl"], &[], out)?;
    Ok(())
}
```

### 4. src/main.rs

```rust,ignore
include!(concat!(env!("OUT_DIR"), "/qsl_gen.rs"));

fn main() -> qsl::QslResult<()> {
    let user = User {
        id: 42,
        name: "Ada".into(),
    };
    let bytes = user.serialize_checked()?;
    let restored = User::deserialize_checked(&bytes)?;
    assert_eq!((restored.id, restored.name.as_str()), (42, "Ada"));
    println!("{}: {} ({} bytes)", restored.id, restored.name, bytes.len());
    Ok(())
}
```

Run cargo run. Expected output:

```text
42: Ada (15 bytes)
```

The schema describes an owned u64 and a String containing 1–100 UTF-8 bytes.
build.rs generates qsl_gen.rs under OUT_DIR. The application includes the generated
type and calls its checked encoder and decoder.

## Format and safety rules

- Required fields always precede optional fields.
- String bounds count UTF-8 bytes; array bounds count elements.
- safety enables checked deserialization. Explicit unsafe APIs remain available;
  callers guarantee complete valid frames and sufficient, correctly aligned storage.
- Checked reads validate lengths, domains, UTF-8, optional metadata and MAX_DATA_SIZE.
- Each compressed-string run is bounded by the actual restored size before reserve
  or writes. A compressed length header does not prove the decoded size.
- The schema and wire-affecting options define the format. Peers coordinate changes.

## Optional mechanisms

| Mechanism | Purpose |
|---|---|
| aggressive | Bounded inline ownership within STACK_LIMIT |
| qps=Q2/Q4/Q8/Q16 | Lossless scalar numeric packing; qps defaults to Q16 |
| predict_seq | Length-derived optional-state index |
| opt_table | Optional field tag to reader dispatch |
| lifetime | Borrowing supported raw fields |
| decompress=true | Independent QSL-LZ string compression |
| transmutate | Explicit native-layout COPY or overlay |
| QSL_RT | Bounded static output slots for eligible schemas |

Attributes are opt-in. MAX_DATA_SIZE defaults to 65535 useful bytes and also limits
the input frame. STACK_LIMIT defaults to 256 data bytes per inline buffer.
Larger ordinary COPY strings and arrays use String/Vec. Fixed native Transmutate
requires an explicitly sufficient limit.

QPS does not quantize strings, arrays or their lengths. QSL-LZ is a separate codec.
predict_seq and opt_table are independent mechanisms and may be combined.

## Compiler crates in 0.2.0

The compiler is separated into `qsl-lexer` (source collection and analysis) and `qsl-interpreter` (Rust generation). `qsl` retains runtime I/O and compatible public imports. The facade and both compiler crates are version 0.2.0. The unchanged procedural implementation crate remains at 0.1.0.

One `QslSchemaBuilder` owns the schemas and DEQ settings. Backends borrow this data through `SchemaBackend`; each backend owns its output and error types. Import the extension trait to choose Rust generation:

```rust
use qsl::prelude::*;
let builder = QslSchemaBuilder::from_source("&Packet[safety]{u64 id;}")?;
let rust = builder.use_interpreter()?;
assert!(String::from_utf8(rust)?.contains("pub struct Packet"));
# Ok::<(), Box<dyn std::error::Error>>(())
```

For files, `build_qsl_schem("schemas")?` collects sorted QSL/DEQ files without generating code. `QslSchemaBuilder::from_files` accepts explicit paths; `from_files_with_rust` adds explicit Rust template paths. `use_interpenter()` is a spelling-compatible alias.

The shared schema collection stays unchanged. Rust storage and overlay lowering belong to the Rust backend. A future LLVM crate can implement the same backend trait and add `use_llvm()` independently. LLVM generation is not implemented, and Rust-specific custom codecs require an explicit target ABI mapping.

Existing `QslInterpreter::generate`, `generate_parsed`, `prepare_schemas`, `generate_prepared`, `build_qsl_files`, error types and import paths remain available. `AnalyzedModule` names the same collection as `QslSchemaBuilder`. The parser shares `Lexer`'s scanner, and `PreparedModule` describes Rust-target preparation.

## Platform-independent runtime in 0.2.0

The Windows-specific native socket and IPC-region modules, the `native` Cargo feature and the `windows-sys` dependency have been removed. `Serializable::serialize` and `BorrowSerializable::serialize` consistently return `Vec<u8>`; `serialize_to` accepts a byte slice. `SerOut` remains a platform-independent aligned buffer, and native-layout COPY/LIFETIME generation remains available. This is an API change from the removed native feature; the former default Vec/slice API is preserved.

## Optional dispatch and schema migration

0.2.0 changes bitmap encoding: only optional fields have bits, with a little-endian u8/u16/u32/u64/u128 selected by optional count. Marker 1 is the most significant bit; the set-bit loop reads present optionals in descending marker order. Old BM frames require coordinated peer migration. Ordinary count/tag headers are unchanged. `opt_table` chooses reader functions; `predict_seq` derives presence from length and is inactive under BM.

```qsl
&Packet[safety,optionals=bitmap,opt_table] { u64 id; u16? a; u8? b; }
```

A named `aggressive_transmutate` region produces a real nested Rust type and parent field. Checked COPY and aligned LIFETIME validate before exposing values; explicit unchecked methods remain available.

## Explicit custom scalar wrappers

```rust
qsl::qsl_primitive!(pub struct DeviceId(u32);range=(1,100););
use qsl::QslCustom;
assert!(DeviceId(0).qsl_validate_values().is_err());
```

The macro checks an integer tuple wrapper's representation and domain, retains QslCustom hooks and supplies a compact whole-byte rank codec. Register the same type with `QslSchemaBuilder::new().with_primitive::<DeviceId>("DeviceId")?` before `.with_source(...)`. For native regions, explicitly opt into `qsl::qsl_native_primitive!(DeviceId,u32);`. Arbitrary user codecs are not automatically reinterpreted or merged into scalar register groups. [Complete migration and constraints](https://github.com/zadr0/QSL/blob/v0.2.0/docs/migration-0.2.0.en.md).
