# Проверка арифметики QPS в Lean 4

Версия закреплена в `lean-toolchain`: Lean 4.35.0. Проект использует Std, без Mathlib и внешних пакетов.

```powershell
lake -d proofs build
```

В `QPS.lean` проверены 18 теорем: точное разложение индекса на квант и остаток; извлечение младшего и старшего разрядов; инъективность пары разрядов при соблюдении границ; восстановление отсутствующей и присутствующей длины; отличие пустого присутствующего поля; сохранение порядка префиксных смещений; пример неоднозначной суммы; граница u32; подсчёт единичных конечных разностей; сохранение суммарного размера при разворачивании блоков полей. Для payload дополнительно проверены восстановление числового значения из ранга, точность частного с остатком и инъективность пары операндов.

Комментарии формулируют предусловия. Пропущенных доказательств (`sorry`) и добавленных аксиом нет. Доказательства относятся к арифметической модели. Связь с Rust-кодом, масками `popcnt`, little-endian кадром и реальными смещениями проверяется исчерпывающими тестами и golden vectors. Это не формальная верификация Rust, аллокатора, LLVM или процессора.

Нельзя заменять взвешенные/отрицательные разности простым числом выставленных битов. Генератор отклоняет такой кандидат. Режимы ранжирования/остатков, не включённые в runtime, не объявляются доказанными реализациями.


Для числового индекса событий проверены добавление граничного признака, монотонность индекса по длине и точность индексов 0/1/2 для двух однобайтовых полей. Это математическая модель, а инструкции cmp/setcc/sbb проверяются отдельно по release ASM.


## Deserialization modernization / Модернизация десериализации

Modernization.lean adds exact read-window bounds, 16-byte splitting, initialized-prefix access/drop bounds, signed rank restoration/injectivity, bitmap None/Some(0), static cache capacity, hybrid frame boundaries/budgets, strict inline eligibility and slot-count conservation.

Модели проверяются Lean 4.35 без Mathlib и допущенных доказательств. Они не доказывают корректность Rust pointers/provenance, атомарной модели памяти, LLVM или WaitOnAddress/futex. Эти части проверяются контрактами API и исполняемыми тестами, включая защищённую страницу на Windows и конкурентные lease.

Run from the repository root: lake -d proofs build.
